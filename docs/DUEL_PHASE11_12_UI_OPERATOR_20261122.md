# KESO DUEL — Roadmap A Phase 11/12 第二分割（2026-11-22）

## 実装対象

Phase 11：
- KESO PLAY 決闘画面に、認証済みサーバー権威の日替わりCPU戦を接続する。
- 本日種目プレビュー → サーバー選定の対局作成 → 盤面操作 → セッションIDで再開。既存６種目に対応。戦績・勝敗・CPU手・秘密情報・報酬はサーバーで確定する。
- 追加KPなし。PvE報酬は Phase 9 でユーザー承認済みの設定のまま。既存の「ブラウザ内練習」とサーバーCPU戦は別物として表記する。
- HTTP通信エラーによる不明結果は同じ操作IDで再試行する。複数の新規操作を自動送信しない。

Phase 12：
- 既存の `duelOperationsAudit` と新規の `duelPreservationExport` を、認証済みKPセッションかつ**サーバー側で暗号化済み所有者設定が一致した場合だけ**提供する。
- 所有者設定は既存の `privateCasinoAllowed` を再利用。設定が未構成または無効な場合は安全側で運営画面を非表示にする。画面の自己申告・表示名一致で開放しない。
- 集計はギルド内の進行中件数・90日超の終了済み件数のみ。要求のたびにSQL `SELECT` を行う。所有者の明示操作で、決闘画面が表示中かつタブが可視の場合に限り約15分おきに集計を更新する。切断、画面移動、アプリ終了、不可視タブでは実行しない。**サーバー側の無人定期実行・24時間監視・異常通知は未実装**。低負荷のため勝手なCron追加はしない。
- 明示操作による「確定済み試合スナップショット」は、PvE/PvP各直近50件の公開結果フィールドだけをローカルJSONとして保存する。**すべての履歴・原本・復元用バックアップではない**。ギルド限定。ユーザーID、秘密手札、賭け金、KP台帳、認証情報を返さない。
- SQL `SELECT` のみで、D1書き込み・削除・報酬増減・自動復旧操作は行わない。
- D1節約モードでは管理監査・保存照会を停止する。認証済み実機、運営者表示、ローカル保存、ログの実運用確認は引き続き未確認。

## 今後の残件
- Phase 11：専用チャレンジ履歴・挑戦経過の改善、アニメーション・操作ガイドの磨き込み、既存６種を超える新ゲームの設計・実装。CPU戦とPvPは互いに勝率補正を適用しない。
- Phase 12：定期監査の実行主体、D1コスト上限、異常通知のルール、完全な復元可能バックアップ、復旧演習、管理操作の監査証跡とアクセス失効手順。無断の自動削除・追加課金なし。

- Phase 8：実端末での操作品質・２人実対戦の遅延、DO実使用量など人が必要な項目は未確認。
