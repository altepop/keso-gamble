# デス判定の通知欠落の修正（2026-11-07）

報告：00:37ごろ、予約済みアンレなのに通常のKP付き速報だけが届き、コンペ行き等の判定がなかった。

## 再現できた不具合

監視開始時に、取り消されていない全予約を `Map<riotId,mode>` にしていた。同じ人に「以前に試合が確定したアンレの予約」と「次のスイフトの予約」があると、一方が上書きされる。その結果、すでに予約に結び付いているアンレが通常試合として扱われる。順序を指定していないSQLの返却順次第では、新しいアンレ予約自体も古い別モードの履歴に隠れる。

SQLiteで同じ症状を再現し、修正前は通常勝敗だけ、修正後は「コンペ行き確定」「次はコンペへ出頭」が出ることを確認した。本番の特定試合が同じ原因かは、別途D1の予約・期限・試合への結び付きの確認が必要。

## 修正

- 人ごとにモードの集合を保持し、予約履歴の異なるモードを落とさない。実際の対象判定は従来どおり、モード・開始/終了時刻・予約期限・取り消し・対象試合IDをDBで照合する。
- 詳細データの再取得にも全モードを引き継ぐ。最終ラウンドの判定や一度確定したデス情報の保存は既存のまま。
- 通常速報として保存されていた試合をデス判定へ直す際は、本文だけでなく保存モードも更新し、同じDiscord投稿を編集する。逆向きに取り消し済みデス投稿を通常扱いへ変えて再送することはしない。
- 通常アンレの扱い・KD/ACS/ラストデスの条件・次の1試合のみ・2時間の予約期限は変更しない。
- 既存の誤った速報は、その試合がAPIの直近履歴に残り、該当予約が有効と確認できた場合に通常の監視で修正される。履歴外・期限外を勝手にデス判定へ変更しない。

## 本番の読み取り専用診断

`Death verdict incident diagnostic (read-only)` を用意。main反映時に一度実行し、その後はActionsから手動実行できる。初期の対象時刻は2026-11-07 00:37 JST。既存のCloudflare用GitHub Secretsを使い、SELECT以外は拒否する。

終了時刻が報告時刻の30分前〜10分後にある最大20件について、モード・保存済み判定の有無・Discord投稿IDの保存有無・前24時間の予約とその期限/取消/結び付きだけを表示する。Riot ID・Discord ID・試合/予約ID・通知本文・秘密値は出力しない。通知DBに開始時刻はないため、終了時刻のウィンドウ内にあるだけで予約成立とは断定しない。診断そのものはDB・Discord・残高を変更しない。
