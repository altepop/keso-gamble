# 公営競技（競馬・競艇・競輪）の仕様

2026-10-27。ユーザーと Claude Code の検討結果。未実装。他ゲーム連携は Draft PR #26 の設計と突き合わせて調整する。

表記: **【決定】** はユーザーが決めた事項。**【提案】** は数値・方式の候補。**【未決定】** は判断待ち。

## 1. 目的

KPを増減させる「リスクで稼ぐ」軸に、走る様子を見て楽しめる公営競技型ゲームを追加する。仲間内の煽り合いで笑えることを最優先にする。

## 2. 前提と制約

- 画面は GitHub Pages の静的配信。描画は Canvas 2D から始め、演出が足りなければ描画部分だけ PixiJS へ差し替える。3Dは使わない。【決定】
- 着順・配当・決済は Worker（`services/valorant-results`）が確定する。ブラウザーは確定済みの結果を再生するだけで、結果や残高を提出しない。現行の架空株・ルーレットと同じ方針。
- 描画ライブラリ・画像はリポジトリに同梱する。Activity 内では外部CDNへ接続できない前提。
- 音は出さない（現行の通話音声への配慮を維持）。実況は文字で行う。
- 実在の競走馬・選手・団体名、実際の映像・ロゴは使わない。
- KPは現実のお金・商品と交換できない。

## 3. 開催形式

| 競技 | 開催 | 頭数 | 位置付け |
| --- | --- | ---: | --- |
| 競馬 | 15分おき・24時間（1日96レース）【決定】 | 8頭【提案】 | 主力。地方競馬くらいの頭数で当たりやすく【決定】 |
| 競馬・目玉 | 平日は朝・昼・晩・0時、土日は増やす【決定】 | 10頭【提案】 | 賞金・演出を豪華に |
| 競艇 | 17:00〜23:00【決定】 | 6艇 | 配当が高め【決定】 |
| 競輪 | 22:00〜翌4:00【決定】 | 7車【提案】 | 配当が高め【決定】 |

利用者は日勤の社会人を想定する【決定】。時刻はすべて日本時間。
平日の主な活動時間は 19:00〜翌1:00【決定】。平日の目玉・冠レース・告知はこの時間帯に寄せる。

- 競艇と競輪はどちらも6時間。重なりは 22:00〜23:00 の1時間【決定】
- 平日の目玉レース: 8:00、12:30、21:00、0:00（時刻は【提案】、0時は【決定】）
- 土日の目玉レース【提案】: 10:00、12:00、14:00、16:00、18:00、21:00、0:00
- 平日の夜は冠レース（名前のついたレース）を組む【決定】。日中に起きた出来事（3連敗など）の冠レースは、その日の 19:00〜翌0:45 の枠に入れる【提案】。
- 土日は冠レースを大量に組む【決定】。【提案】出来事が起きた直後の枠に入れるほか、10:00〜翌1:00 は毎時1レース以上を冠レースにする。出来事が足りない時間は、ミーム・友人の名前・馬の二つ名・殿堂入り馬から自動で冠レースを作る（例:「◯◯号おつかれ引退レース」「ATMレース」）。名前を使う冠レースは本人の煽りレベルに従う。
- 出走表は発走の15分前に確定し、ベットは発走1分前に締め切る【提案】。
- 誰も見ていない時間帯も、Worker の定期実行で出走表作成・締め切り・決済を自動で行う。

### ノーコンテスト（不成立）【決定】

- 締め切り時点で **ベットが0件** かつ **馬主のいる馬が出走していない** レースは不成立にする。
- 不成立のレースは着順を決めない。成績・二つ名・引退までの出走数・賞金・Bot投稿・検証の集計に含めない。
- 不成立の判定は締め切り時点の情報だけで決まり、着順とは無関係なので、オッズの検証（還元率・的中率）は歪まない。
- 例外【提案】: 目玉レースと冠レースはベットがなくても必ず行う（ネタとして成立させるため）。
- 【提案】オッズの計算は、出走表を誰かが初めて開いた時点で行う。誰も開かないレースは計算しないので、深夜の Worker の負荷が減る。開かれないまま締め切られたレースはベットがないので、馬主の馬がいなければそのまま不成立になる。
- ベットせずに観戦だけしている人がいても不成立にする【決定】。画面に「投票がなかったため不成立」と表示する。
- 公開済みのシード値ハッシュは、不成立でもレース後にシード値を公開し、再利用しない。

## 4. 券種とオッズ

| 競技 | 券種【提案】 |
| --- | --- |
| 競馬 | 単勝・複勝・ワイド・馬連 |
| 競艇 | 2連単・3連単 |
| 競輪 | 2車単・3連単 |

- 参加人数が少なくても成立するよう、**胴元が出す固定オッズ**にする（賭け金を分け合う方式は使わない）。
- 胴元の取り分は設けない。オッズは当たる確率どおりの純粋な運ゲーにする（還元率100%）【決定】。
- 払い戻しに上限を設けない【決定】。大当たりで増えたKPは、超高級な商品・馬（ガチャボックス）で使ってもらう。
- KPの増えすぎは次の2つで抑える【決定】。
  - **1週間の購入上限**: 1人が1週間に買える馬券（舟券・車券を含む）の合計額。
  - **1日の交換上限**: 1人が1日にKPを指令・商品へ交換できる上限。大当たりした人がコンペ指名などを連発できないようにする【決定】。
  - ガチャボックスの購入も交換上限に含める【決定】。
  - 【提案】交換上限は金額ではなく回数で数える。ボックスや超高級品は数十万〜数百万KPなので、金額の上限にすると高い品がいつまでも買えないため。

| 上限【提案】 | 値 | 理由 |
| --- | --- | --- |
| 1週間の購入上限 | 50,000 KP | コンペ1勝900 KP なので、毎日数試合遊ぶ人の1週間の稼ぎの2〜3倍。運ゲーでも1週間で溶かせる額に限りがある |
| 1日の交換上限 | 3回 | 指令・ガチャボックス・超高級品を合わせて1日3回まで。大当たりしても、1日に出せる指令は最大3件 |
| 指令の制限（既存） | 相手1人につき未達成1件 | そのまま維持 |
| 1回のベット | 100 KP 以上、100 KP 単位 | 少額でも遊べるように |

1週間は月曜0時から（既存の `/valo week` と同じ）。

### オッズは本気で作る【決定】

見た目と実況はふざけてよいが、オッズは数学的に正しいものにする。

#### 結果とオッズを同じモデルから出す

- レースの結果を決める関数を一つだけ作る。入力は出走馬の能力・調子・枠・馬場・シード値、出力は着順。
- 本番の着順はこのモデルから本番のシード値で1回抽選して決める。オッズは同じモデルの確率を厳密に計算して出す（実装済み）。
- アニメーションは確定した着順に合わせて動かすだけで、着順を決めない。珍事（逆走・草を食べる等）のうち着順に影響するものは、この関数の中で確率として扱う。見た目だけの珍事は着順に影響させない。
- そのため、表示されたオッズは実際の当たりやすさと一致する。

#### 着順のモデル（実装済み）

- 各馬の強さ = exp(鋭さ × (基礎能力 + 調子 + 枠の有利不利 + 展開の向き不向き))。馬場がぬかるむほど鋭さが下がり、波乱が増える。
- 着順は Plackett–Luce 型で決める: 1着は残りの馬から強さに比例した確率で選び、2着以降も残りの馬から同じように選ぶ。
- 展開: 逃げ・先行の馬が多いとハイペースになり差し・追込が有利、少ないとスローで前残り。展開は5通り（重み 1:4:6:4:1）の混合で、「能力は上だが展開が向かない」波乱が自然に起きる。
- 出遅れは見た目だけの珍事として、後方でゴールした馬から選ぶ。着順には影響しない。
- 同着は未実装。

#### 厳密計算と精度（実装済み）

- 当初は5万回の試行で数える案だったが、Cloudflare Worker の無料プランの CPU 制限（1リクエスト10ms）に収まらないおそれがあるため、厳密計算に変更した。
- 1着と3着以内の確率は、展開5通り × 上位3頭の並び（10頭立てで720通り）を全部足し上げて計算する。1レース約0.2ms。試行の誤差はない。
- 3連単などの券種も同じ方法で計算できる（競艇6艇で120通り、競輪7車で210通り）。

#### オッズの算出

- オッズ = 1 ÷ その券の確率。0.1倍単位で切り捨て、最低1.0倍（元返し）。切り捨ての分だけ、実際の還元率は100%をわずかに下回る。
- 複勝は8頭以上で3着まで、7頭以下で2着まで（実際の規則に合わせる）。ワイド・馬連も同じ厳密計算で出す。
- 固定オッズなので、ベットが集まってもオッズは動かない。ベット時点のオッズを台帳に記録し、その倍率で払い戻す。
- 同着は実際の競馬と同じく払い戻しを分ける（単勝なら同着の頭数で割る）【提案】。

#### 検証

- 自動テスト（`tests/racing.test.js`、実装済み）で次を確認する。
  - 厳密計算の確率が、同じモデルで2万回抽選した結果と一致する。
  - 1,500レースで、本命と穴馬の予想勝率と実際の勝ち数が一致する。
  - どの馬・券種でも、確率 × オッズ が 0.9〜1.0 に収まる（切り捨て分だけ100%を下回る。必勝法がない）。
- 本番のレース結果も記録し、同じ検証を定期的に行う。

## 5. レースの中身

### 能力

- スピード、スタミナ、脚質（逃げ・先行・差し・追込）、調子、枠順、馬場状態（良・重など）。
- 競艇: 1号艇のイン有利、スタートのタイミング、フライング（返還）。
- 競輪: ライン（選手同士の連携）、打鐘からの仕掛け、先行・捲り・差し。
- シミュレーション部分を共通にして、競技ごとの規則を差し込む。

### 再生と観戦

- Worker が発走時刻・シード値・着順を配る。各端末は「現在時刻 − 発走時刻」から位置を計算するので、全員が同じ展開を見る。常時接続のサーバーは不要。
- 途中から開いた人はその瞬間から観戦できる。過去レースのリプレイも可能。
- 位置の計算（シミュレーション）と描画を分け、確定した着順と画面の展開が一致することをテストする。

### 公平性の検証

- ベット締め切り前に、シード値のハッシュを公開する。レース後にシード値を公開し、結果を後から操作していないことを誰でも確認できるようにする。

### 演出

- 競馬の見せ方は横スクロール（中継風）でしっかり作る【決定】。カメラが先頭集団を追い、直線ではゴール板に向けて寄る。全体の順位は画面上部の帯（隊列図）で常に見せる。
- 競艇・競輪は後から作る【決定】。見せ方は作るときに改めて決める。【未決定】
- 段階: スタート → 位置取り → 最終コーナー → 直線の追い比べ。ハナ差は写真判定とスロー再生。
- 珍事（まれ）: ゴール前で草を食べる、騎手だけ落ちて馬がゴール、など。着順に影響する珍事は確率をオッズに含める。
- 「視差効果を減らす」設定では簡易表示にし、結果は必ず文字でも出す。

## 6. 馬と馬主

### 馬の名前【決定】

- 友人の名前: 本人が許可した場合だけ作る。いつでも取り消せる。
- ミーム: 既存の `meme-quotes.json` などを候補にする。
- 馬主の命名: KPで馬を購入して自由に命名する。不適切な語は弾く。

### 馬主制度【決定】

- KPで馬を購入すると出走馬に加わる。勝ち星（着順）に応じて馬主にKPが戻る。
- 1人の所有は3頭まで。
- 出走の頻度はランダム。
- 出走枠は馬主のいる馬を優先し、空いた枠を野良の馬で埋める。馬主の馬が多すぎるときは抽選。
- 売却は購入価格の10〜20%で買い取る。【提案】出走数が少ないほど20%に近く、引退間近は10%。
- 引退は早め。【提案】20走で引退し、殿堂ページに戦績と二つ名を残す。【未決定】走数

### ガチャボックス【決定】

等級ごとに値段の違うボックスを用意し、買うまで能力はわからない。超超高級馬も存在する。

| ボックス【提案】 | 価格【提案】 | 中身の傾向 |
| --- | ---: | --- |
| ノーマル | 3,000 KP | ほぼ下級馬。ごくまれに中級 |
| シルバー | 15,000 KP | 中級馬が中心 |
| ゴールド | 60,000 KP | 上級馬が中心 |
| プラチナ | 250,000 KP | 上級〜エリート級 |
| レジェンド | 1,000,000 KP | エリート級以上。超超高級馬はここからのみ |

- どのボックスにも、低い確率で一つ上の等級の馬が入る。逆に高いボックスでも外れ馬が出るとネタになる。
- 【未決定】等級ごとの排出率。排出率は画面に公開する。

### レースの格と賞金【決定】

- 賞金はレースの格（出走馬の強さ）で変わる。最安のレースは 1着 1,000 / 2着 400 / 3着 200 KP。
- 【提案】出走馬の平均能力から格を決める。

| 格【提案】 | 賞金の倍率【提案】 |
| --- | ---: |
| ザコ戦 | 1倍（最安） |
| 中堅戦 | 3倍 |
| 強豪戦 | 10倍 |
| エリート戦 | 30倍 |
| 頂上決戦 | 100倍 |

- 出走馬は能力の近い馬で組む。高級馬は格の高いレースに出て大きな賞金を狙う。
- 目玉レースは格を一段上げる【提案】。
- 【未決定】ボックス価格と賞金・引退走数の釣り合い。1頭が引退までに稼ぐ賞金の期待値を、等級ごとに自動テストで計算して調整する。

### 実装済み（2026-10-27）

- 本番口座の競馬画面の「馬主」でボックスを開ける（`horse-buy`）。価格と排出率は上の表の提案値のとおり。名前は1〜12文字で、記号・URLは不可。
- ボックスの購入は指令と合わせて1日3回まで（日本時間0時に戻る）。持てる馬は3頭まで（引退・売却した馬は数えない）。
- レースの格は発走時刻から決まる（ザコ戦50%・中堅戦25%・強豪戦15%・エリート戦7%・頂上決戦3%、大きなレースは1段上）。野良の馬の強さは格に合わせる。
- 馬は自分の等級と同じ格のレースに、受付開始のときに40%の確率で出走する（`kp_race_entries`、前後1時間は休む）。誰もActivityを開かなくても、毎分の cron が出走を決める。出走が決まった後は変わらないので、馬券のオッズと精算が食い違わない。
- 馬主の馬が出るレースは、馬券がなくても行う。賞金は 1着1,000 / 2着400 / 3着200 KP × 格の倍率（1・3・10・30・100倍）。精算は cron が1回だけ行い、台帳から馬主の口座へ入金する。
- 20走で引退して殿堂に残る。売却は購入価格の20%（新品）から10%（引退間近）まで出走数に応じて下がる（`horse-sell`）。売却した馬がその後のレースで入着しても賞金は出ない。
- 出る馬一覧・稼ぎchの投稿に「馬主 ◯◯」を表示する。

### 二つ名・本人の名前の馬（実装済み 2026-10-27）

- 賞金の精算時に、馬主の馬の着順・単勝の倍率・1番人気だったかを `kp_horse_runs` に記録し、直近20走から二つ名を付ける。優先順: 20倍以上で勝った「気まぐれの悪魔」→ 1番人気で4着以下が2回「人気詐欺」→ 未勝利で2着3回以上「永遠の二番手」→ 直近5走すべて4着以下「歩く戦犯」。出る馬一覧・馬主パネル・殿堂・稼ぎchの出走表に表示する。
- 誰かの名前の冠レース（煽りレベルが標準・全開の人だけに組まれる）には「◯◯号」が出走する。能力は格の平均より低め、走り方は「最後に一気」。出走は冠レースの決定と同時に決まり、受付開始後は変わらない。
- 「◯◯号」が3着以内なら賞金は本人に入る。さらに、本人以外がその馬に賭けた額の5%を見舞金として本人に入れる（外れても入る）。

### 二つ名（成績から自動で付与）

- 連敗中: 「歩く戦犯」「ATM」「キャリー待ち」
- 1番人気で負ける: 「人気詐欺」「期待の裏切り者」
- 万年2着: 「永遠の二番手」「シルバーコレクター」
- たまに大穴で勝つ: 「気まぐれの悪魔」「1年に1回だけ本気」

## 7. 他ゲームとの連動

4人以外の参加者も対等に遊べるよう、VALORANT専用にせず「活動」としてまとめる（Draft PR #26 の多ゲーム対応と合わせる）。

- 愛馬の調子は、馬主の直近の活動で決まる。対象: VALORANT、PR #26 で接続予定のゲーム（雀魂・Steam・Minecraft Realms）、VCT QUIZ、KESO LOOP、通話滞在（[通話KP](VOICE_KP.md)）、KESO PLAY 内の行動（ログイン・馬小屋での調教・予想への参加）。
- どのゲームでも上がる調子の量は同じ。ゲーム連携がない人も KESO PLAY 内の行動で好調にできる。
- 調子による能力補正は ±5% 程度、1日に上がる量にも上限【提案】。
- 調子は出走表確定時に決めて公開し、オッズへ反映する。馬券を買う側の期待値は変わらない。
- 友人の名前の馬は、本人が許可した場合だけ本人の活動と連動する。
- 友人の試合の勝敗に賭ける案は採用しない（八百長の問題）。

### 実装済み（2026-10-27）

- 馬主の馬（と本人の名前の馬）の調子は、出走が決まるとき（受付開始時）に、その人の直近の遊びから決めて `kp_entry_conditions` に固定する。後から遊んでもそのレースの調子は変わらない。

### 投稿先【決定】

- 「稼ぎch」を新設済み。競馬に限らず、KESO PLAY 関連の投稿（架空株・ルーレット・指令・KPの入金・ガチャ・称号など）はすべて稼ぎchへ投稿する。
- 試合速報は今のチャンネルのまま。【提案】速報の末尾には一言（「3連敗、今夜21:15『◯◯戦犯レース』開催決定」など）だけ付け、詳細は稼ぎchへ流す。
- 投稿にはチャンネルIDではなく、稼ぎchの Webhook URL を使う（実装済み）。Bot トークンを使わずに済み、権限がそのチャンネルへの投稿だけに限られるため。
- 設定手順（1回だけ・管理者）:
  1. Discord で稼ぎchの「チャンネルの編集 → 連携サービス → ウェブフック → 新しいウェブフック」を作り、「ウェブフックURLをコピー」する。
  2. Cloudflare → Workers & Pages → valorant-results → 設定 → 変数とシークレット → 追加。種類を Secret、名前を `KP_EARNINGS_WEBHOOK_URL` にし、コピーしたURLを入力して保存・配置する。
  3. URLをチャット・Git・PR・ログに貼らない。
- 未設定の間は何も投稿せず、投稿の予約もしない（設定した瞬間に過去分が一気に流れることはない）。指令の通知は従来どおり速報チャンネルに出る。
- 設定後は、指令の発令・達成の通知も稼ぎchへ移る。試合速報への「この試合 +900 KP」の追記は速報チャンネルのまま。
- 投稿は ID 付きで `kp_posts` に予約し、毎分の cron が送る。送信失敗は次の cron で再送し、同じ投稿を二重に出さない。
- 現在の投稿: 大きなレースの出る馬一覧と倍率（締切の15分前から1回）、大きなレースの結果、通常レースは1回の払い戻し10,000 KP以上か、5,000 KP以上の外れがあったときだけ結果を投稿。結果には着順、各自の的中・外れ、シード値を載せる。
- 煽りレベルの実装までは、登録済みの4人だけに強い煽り、それ以外の参加者には控えめな文言を使う。
- 実況・煽りの文言は、既存の6種類の口調・ミーム引用・`taunts.json` に競馬用を追加して使う。相手の煽りレベルに従う。

### 本番口座での競馬（段階2の実装）

- 出る馬一覧とオッズは公開の計算で、ブラウザーと Worker が同じ値を出す。
- 着順は Worker がレースごとに作るランダムなシード値で決める。シード値は D1 の `kp_races` に保存し、発走までは SHA-256 ハッシュだけを公開する。発走後にシード値を公開し、ブラウザーがハッシュと照合して「一致」を表示する。
- 馬券は既存の口座操作（`kp_operations`）の `race-bet` として扱う。同じ操作IDの再送では二重に引き落とさない。馬券と1週間の購入額は各自の口座状態に保存する。
- 精算は毎分の cron が行う。レース終了後、保存されたシード値で結果を出し、払い戻しを同じ仕組みで1回だけ入金する。読み込んだ後に口座が変わっていたら書き込まず、次の cron でやり直す。
- 不成立: 大きなレース以外は、誰かの口座に馬券があるレースだけを行う。
