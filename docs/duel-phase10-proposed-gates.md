# KESO DUEL — Roadmap A Phase 10 承認待ちゲート記録（提案のみ）

状態: **PROPOSED / 全5ゲート未承認**。これは設計判断用の文書であり、承認・本番設定・実行権限を付与しない。既存の純粋関数テストが成功していてもPhase 10の完了判定にはならない。

## 1. 観戦の公開ポリシー — PROPOSED
- 決定が必要: 誰がどの対戦を観戦できるか、参加者の同意をいつ取得・撤回するか、ギルド境界をどう確認するか。
- 安全側の提案: 初期状態は非公開。本人認証・所属ギルド一致・対戦単位の明示許可をすべて要求し、許可情報が欠けたら拒否する。
- 承認前の制約: 観戦の公開ルート・第三者配信を作成・開放しない。
- 確認資料: 許可/拒否表、撤回後の挙動、秘密手札・トークン・回答の非露出回帰。

## 2. 観戦同期方式 — PROPOSED
- 決定が必要: ポーリングかイベント配信か、再接続・低速回線・複数端末での整合性、反映許容時間。
- 安全側の提案: リビジョンとスナップショットの設計を先に検証。重複や古い更新を無害化し、未認可時は同期を開始しない。
- 承認前の制約: 実サービスへの購読、外部通知、実Durable Objects観戦同期を有効化しない。
- 確認資料: リビジョン境界・再接続・順序逆転・負荷・遅延の測定と手順。

## 3. 大会規模・方式 — PROPOSED
- 決定が必要: 参加人数、募集・棄権・不戦勝、対戦方式、同点時扱い、対戦開始条件。
- 安全側の提案: 提案ブラケットの決定性・人数境界・BYEの検証結果だけを設計資料として扱う。コード上の最大128人は大会規模の承認ではない。
- 承認前の制約: 大会募集、対戦生成、KP精算、賞品付与、トーナメント公開を起動しない。
- 確認資料: 具体的な人数・方式の承認記録、キャンセル時の扱い、CPU参加と不正対策。

## 4. 演出音声の許可 — PROPOSED
- 決定が必要: 音源利用権、ユーザー/チャンネル単位のopt-in、消音・低減動作、Discordへの送信有無。
- 安全側の提案: テキストのみ・ミュートを既定とし、公開承認と音声承認をそれぞれ別に要求する。
- 承認前の制約: 音楽・読み上げ・通知音の再生、実Discord投稿を行わない。
- 確認資料: 権利確認、拒否優先順位テスト、音量・アクセシビリティ検証。

## 5. 運営者ロール — PROPOSED
- 決定が必要: 権限を持つ主体、操作種類、監査記録、緊急停止・権限失効、誤操作の復旧手順。
- 安全側の提案: 権限ゼロを既定とし、明示されたサーバー側認可と操作監査を要求する。
- 承認前の制約: 大会開始・公開設定・D1書込・報酬配布を行わない。
- 確認資料: 操作別権限表、無権限拒否回帰、停止テスト。

## 品質・リリースゲート
- 5ゲートは**個別の人間の明示承認**がそろうまでPROPOSEDを維持する。「テストが成功した」「準備コードがmainにある」は承認の代わりにならない。
- Phase 9報酬有効化は別の承認事項であり、本書を根拠に本番ポリシーINSERT、D1更新、KP配布を行わない。
