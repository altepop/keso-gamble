# スパイクラッシュの育成報酬

2026-10-29。実装：`services/valorant-results/src/spikerush-growth.ts`。

画面での説明は「履歴に応じて補正されます。」。確定した金額と基礎・補正・端数精算の内訳は本人の入出金履歴と速報に残す。能力解放の全体告知や、稼ぎやすさのランキング表示は行わない。

## 対象

新ルールの初回起動時にD1へ`spikerush_growth_started_at`を一度保存し、それ以降に開始したスパイクラッシュだけを対象にする。登録日時より前の試合も対象外。既に支給した試合は旧ルールの金額を維持し、過去の称号用熟練度からは成長させない。

サーバーの試合履歴から、完了済み・本人1人・重複のない10人・各5人の2チーム・勝敗と4対0〜3の最終スコア・時刻・既知エージェント・非負整数のK/D/Aを確認する。K+Aが2未満は育成・支給対象にしない。個人の完走やAFKを必ず判定できるという意味ではない。欠損、未知エージェント、通常と異なる終了スコアは推定で支給しない。

不明なデータは次回の監視時に再評価する。この待機はAPIで再取得できる最近の試合の範囲に依存し、無制限の過去履歴を取得する仕組みではない。

## 名簿とロール

`services/valorant-results/spikerush-roster.json`は2026-10-29確認の29人で固定した。

- Riot公式一覧：https://playvalorant.com/en-us/agents/
- UUID・ロール：https://valorant-api.com/v1/agents?isPlayableCharacter=true&language=en-US （コミュニティAPI）

コミュニティAPIにあっても公式一覧に載っていなかったHushは対象にしていない。エージェントIDを優先し、IDがないレスポンスだけ英語の正規名と完全一致で照合する。曖昧な名前の近似照合をしない。

ロールの全キャラで2有効試合ずつ終えると永久解放。勝利は必須ではない。新キャラが追加されてもこのversionの名簿は自動更新しない。名簿変更は別versionで扱い、既存の解放フラグを削除しない。

D＝デュエリスト、I＝イニシエーター、C＝コントローラー、S＝センチネル。

- `C_r = ロール内の各キャラのmin(有効回数,2)の合計 / (名簿人数×2)`
- `U_r = 全員2試合を達成済みなら1、それ以外0`。取得済みフラグは永久。
- 今回分で達成した能力は次の試合から適用。

## 成長と計算

`N`は今回より前の有効試合数。`H=clamp((N-5)/35,0,1)`。
最初の6試合はH=0。40試合を終えるとH=1になるが、全ロールの解放には最短58試合（29人×2）が必要。

勝ちW=1、負けW=0、キルK、アシストA、デスDとする。

```text
B = 20 + 20W
X = (4 + 2C_D + 2U_D) × min(K,15)
Y = (3 + 1.5C_I + 1.5U_I) × min(A,10)
Z = (10C_S + 10U_S) × min((K+A)/max(1,D),2)
M = 1 + H × (0.10C_C + 0.15U_C)
T = (B + H × (80 + X + Y + Z)) × M
```

日次の有効試合数は今回を含め、終了時刻のUTC日付＝朝9時JST区切りで数える。

- 1〜10試合目：F=1
- 11〜15試合目：F=0.5
- 16試合目以降：F=0.1

今回を含む直近最大5試合で同じエージェントを使った回数によって、Jは1〜2回=1、3回=0.8、4回=0.6、5回=0.4。

```text
Q = B + F × J × (T-B)
入金 = floor(Q + 前回の端数)
次回の端数 = Q + 前回の端数 - 入金
```

同キャラ・周回減衰は増加分だけに掛ける。基礎額と能力は失わない。朝9時で回復するのは日次枠だけで、直近5試合の反復履歴はリセットしない。

すべてBigInt有理数で計算し、端数を分子/分母で保存する。JavaScript浮動小数で累計支給を丸めない。K/D/Aは0〜1000の整数に制限し、加算側のキル/アシスト/効率は上限で止める。理論上限は勝ち425、負け400 KP/試合。

新しいスパクラ報酬に旧固定額・最下位減点・共通ラッキーを重ねない。既存の借KPの返済処理は継続する。

## 試算と限界

`node scripts/spikerush/simulate.mjs`で現行の純粋計算関数から試算できる。キル6・アシスト2・デス6を全試合固定、日次補正全開、同キャラ減衰なしで比較した例：

| 状態 | 勝率0% | 勝率50% | 勝率65% | 勝率100% |
| --- | ---: | ---: | ---: | ---: |
| 初期 | 20 | 30 | 33 | 40 |
| 名簿順に40試合、解放なし | 160.1 | 170.9 | 174.1 | 181.6 |
| 名簿を2周、全ロール解放 | 233.3 | 245.8 | 249.6 | 258.3 |

実ユーザーの成績分布や所要時間を測定した期待値ではない。全勝率での時給最強は設計目標であり、実測前に保証しない。完成状態でも周回/同キャラ減衰中は効率が下がる。

## 精算と再試行

- `spike_profiles`：guild+PUUIDごとの成長・ロール・直近4キャラ・端数・version。
- `spike_rewards`：安定したguild+matchID+PUUIDキー、金額、計算内訳、次状態、対象日の精算済みイベント。
- `spike_reward_apply`トリガーがプロフィール更新→既存`kp_events`登録→既存台帳/残高更新を同じSQLite文のトランザクションで実行。
- profile versionによる比較更新。競合時は読み直して計算。取得時刻・設定version・表示名ではイベントキーを変えない。
- 元の`kp_inbox`に最小限の確認済み成績を保存し、失敗時は残す。再試行で成長、端数、日次枠を増やさない。
- 結果が遅れて届いた試合は、元の終了日の枠と、その時点で確定済みの成長状態を使う。既存の精算は再計算しない。通常監視で取得したまとまりは既存の開始時刻昇順で処理する。
- 同じイベントは最初の支給額・内訳を返す。通知失敗で再支給しない。

D1には既存サービスと同じ追加テーブルの初期化方式で導入する。schemaと導入開始時刻は初回の原子的なbatchで作成。次のisolateでは開始時刻の存在を1回読むだけでDDLを繰り返さない。旧D1の削除やmigration0005の再適用は不要。

`/api/kp/status`の`spikerushGrowth`で配置されたpolicy、名簿version、開始時刻を確認できる。秘密値や個人の進捗は含まない。

## 新・ロール覚醒 / SPIKE OVERDRIVE（2026-11）

従来の「名簿の各エージェントを2回使うと通常解放」は**廃止せず維持**。そのうえで各ロールの**隠された試練**も満たすと「覚醒」する。試練は基本条件の達成前にクリアしていても保存され、再度達成する必要はない。新機能導入前の既存プロフィールは保持し、古い記録にないK/D/Aや勝利条件を推測して覚醒させない。

- Duelist：1試合12キル以上。
- Initiator：1試合7アシスト以上。
- Controller：**異なる5人**のコントローラーでそれぞれ1勝。
- Sentinel：1試合5キル以上・0デス。

いずれも当該ロールのエージェントで、サーバーから検証できた有効なスパイクラッシュの試合に限る。達成した試合は次の試合から覚醒が適用される。4ロールすべて覚醒したら**SPIKE OVERDRIVE**（永久解放）となる。

### Discord コマンド・ヒントの購入

`/spike status`：本人だけに表示される。通算試合数、各ロールの必要使用回数、各キャラの0/2～2/2、通常解放/覚醒/OVERDRIVEを確認可能。購入前は固有試練の内容・必要数値を**表示しない**。既に達成した特殊実績の有無のみ把握できる。

`/spike hint role:<ロール>`：**各ロール10,000 KPの買い切りヒント**。達成前でも購入でき、解放した条件の数値と進捗を`/spike status`で確認できる。購入しなくても裏で達成を検知し、覚醒と報酬は受け取れる。未登録のRiotアカウント・借KP・残高不足・不正なロールは購入不可。既購入時は再課金されない。

秘密条件の管理・購入記録は本人のリンク済みPUUIDに紐付く。購入は単一の`INSERT ... SELECT wallet.balance>=10000`と同トランザクションの台帳トリガーで原子的に処理。再実行・並列要求は主キーで重複不可。D1の定期ポーリング・個人データの全件走査は不要。

### OVERDRIVEの実額

既存の4ロール強化・有理数の端数精算は維持。通常のロール覚醒1件につき成長報酬に**+35 KP**を加える。全4覚醒ではさらに**+415 KP**。**全覚醒中のみ**11試合以降の日次減衰および同キャラ反復減衰を免除し、すべての試合に同じ成長計算を適用する。

現行の6キル・2アシスト・6デス、全育成済み状態の試算では勝ち約813 KP、負け約788 KP、勝率50％で平均約800 KP/試合。優秀な戦績の理論最大は**980 KP/試合**、上限を**1,000 KP/試合**で検証。真の期待値は各人の実際のK/D/A・勝率・試合時間に依存する。

**既存D1データの保護：** 旧`spike_rewards`の0～425 CHECK制約と全履歴・旧試合金額は変更しない。425超の新規報酬のみ、同じversion CASと`kp_events`台帳トリガーを持つ`spike_overdrive_rewards`へ書き込む。両テーブルの支給を日次試合数・本人の入出金履歴・重複確認で集計する。移行時の旧データ再計算や、プロフィールの削除・再作成を行わない。

ヒント購入は`spike_hint_unlocks(guild,puuid,role)`に1件だけ記録し、同じトランザクションで`kp_ledger`からマイナス10,000 KPとして処理する。別の定期巡回処理や全件検索は追加しない。
