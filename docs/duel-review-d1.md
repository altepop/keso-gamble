# 決闘6モード 品質確認・D1保護
2026-11-07 改善計画（PR #365）

## 今回の対応
- 進行中ルーム優先表示、6モードの実動デモ、iPhone向け五目並べ操作は既存のPR #360〜#362の内容を維持。
- Hit & Blow: 入力中の数字を画面再描画後も維持（ブラウザ内の一時メモリのみ）。40手目で正しく終了。推理履歴を最大40件表示。
- オセロ・五目並べ: 前回受信した盤面との差から「新しく置かれた石」が一つだけ確定できた時に限り、直前の着手を強調。最大12手の**端末内履歴**を表示。再起動やオフライン中の手は復元できないため、全対局履歴とは呼ばない。
- ブラフダイス: 宣言の初期値を直前より強いものとし、入力できない選択肢を無効化。10個・6の目の後は疑いのみ。
- ポーカー: 公開された5枚から役名を計算して併記。勝者・引き分けの判定はサーバー側の元の関数を継続使用。
- 対戦一覧: サーバーがすでに返している直近最大20件から対戦成績、相手別の成績を集計。追加クエリなし。
- 賭け金: 差引損益を表示。50,000 KP以上の申し込み・承認はアプリで2回確認。サーバー側の100〜100,000 KP制限・残高照合・一意な操作IDは維持。
- 手番切替: 対戦画面を見ている間のみ画面内に通知（Discordへの通知投稿はしない）。残り時間はブラウザだけで毎秒表示。
- 復帰: 非表示タブでは自動更新せず、復帰後に最後の取得から6秒以上経過していれば再取得。対局中10秒、招待あり20秒、その他30秒を目安にポーリング。
- 各ゲームを初めて遊ぶ人向けに一行の遊び方説明を追加。

## D1保護
1. 新しいD1テーブル・インデックス・監査用DB書き込み・定期スキャンを追加しない。KP台帳の決済トリガーと原子的トランザクションを変更しない。
2. 対戦の着手履歴・成績・通知・タイマーは、すでに返却済みのJSONとブラウザのメモリのみから作る。
3. 期限切れの精算は既存の5分ごとの処理に任せ、ブラウザから勝手に再決済しない。
4. D1使用量の実測が必要な場合はCloudflareメトリクスで確認する。PRの時点では本番削減率は未計測。

## 実機テスト（2人それぞれのDiscordアカウントが必要）
本番で無断のKP消費を行わないため、本PRはユーザー2人の実口座で賭けを確定していない。ローカルデモ(`duel-demo.html`)は本番API・D1に接続しない。ブラウザテストと別に以下を実施する。
1. 2つの別アカウントで同一サーバー内のKP口座を接続し、お互いが候補に出ることを確認（名古屋・小林・千葉ゆうや・VDK・藤村・石原の名前が正しいことも確認）。
2. オセロ/五目並べ/四目並べ/Hit & Blow/ブラフダイス/5カードポーカーをそれぞれ100 KPで申し込み・承認・着手し、端末を閉じて再参加する。
3. 対戦ごとに両者の表示が一致し、秘密の数字・ダイス・手札が相手へ漏れないこと、勝者が合計200 KPを受け取り、負けた側は100 KPを失い、引き分けでは双方に返ることを照合。
4. 期限切れ/投了/重複タップ/通信切断後の再送で二重決済しないことを確認。50,000 KP以上は実KPを使わずUIの二段階確認に限定する。
5. 失敗時は新規招待・決済を続けず、口座明細と既存のKP台帳を管理者が照合する。

## 範囲外・制約
- 本番Discordへの「手番DM通知」は追加しない（不要な通知・APIアクセスを避ける）。
- 過去30日超の全着手履歴や永続統計DBは追加しない。初期表示は直近20件、古い対戦結果は手動ページング、個別の着手履歴は端末で確認した手のみ。
- 実D1に対する定期異常スキャンは新設しない。既存の対局E2Eテストでゼロサム決済・冪等性・残高不足・重複確定をチェックする。稼働後はCloudflareのD1メトリクスとKP台帳の管理確認で補完する。
- 指令の費用、達成判定、通知、KP付与、対象者、`kp_directives`の行には一切触れない。

## PR #366：追加改善（2026-11-07）
- **確定不能な通信:** 操作を送る前に操作IDと引数を保存し、レスポンスを失った場合は同じIDでしか再確認しない。未確認中は異なるKP操作を遮断。7日以内の同一口座・同一タブの再読み込みでは sessionStorage から復元できる。ブラウザが保存を拒否した場合は同じ画面内の再試行のみ有効。
- **接続復帰:** 最終受信時刻を明示し、エラー時は10→20→40→60秒の上限付きバックオフ。手動更新で即時再確認可能。対局中の正常接続では10秒更新を維持。
- **端末内の盤面履歴:** 受信済みの単一着手差分だけを最大12手、ユーザー別 localStorage に保存する。観測していない着手を補完しない。秘密の数字・手札・ダイスは保存しない。
- **古い対戦結果:** 直近20件より前を「過去の対戦を20件ずつ読み込む」ボタンでオンデマンド取得。 `updated_at,id` キーセットカーソルにより同一更新時刻でも重複を避ける。履歴ロード時は既存メンバーを再取得しない。通常の10/20/30秒自動更新では従来どおり最新20件のみ照会する。全件の自動集計は行わず、戦績は読み込み済み範囲と明示する。
- **ポーカー判定:** サーバーと画面で共有している役判定でワンペアがツーペア扱いになる不具合を修正した。公開されたカードで役の上下と同一役内の比較理由を示す。非公開カードは使わない。
- **KP台帳の異常検知:** 承認時と決着時だけ、対戦IDに紐づく最大4つの既存台帳IDを1回の索引付きSELECTで検証する。参加者・増減額・ギルド・台帳種別を期待値と照合し、不一致は `duel-ledger-integrity-anomaly` としてWorkerのログに記録。タイムアウトの既存5分処理も実際に精算した対象だけ検証する。監査結果は支払いを再実行せず、監査問い合わせが失敗しても既に成立したKP操作を重複送信しない。

### D1負荷と検証条件
- 毎秒タイマー、画面内の手番通知、端末内着手履歴、最終更新時刻は追加D1アクセス **0件**。
- 自動の対戦情報取得は対局中10秒・招待待ち20秒・待機30秒。通信異常時は指数バックオフ。
- 過去履歴はボタンを押したときに限り1ページ20件を追加SELECT。
- KP監査は承認または精算の実イベント1件につき、既存台帳の固定IDを1回SELECT。永続監査テーブル・定期スキャンは追加しない。D1使用量の増分は実測未確認である。
- Cloudflareの本番D1 metricsおよびWorkerの例外ログで、稼働後の負荷・不一致の有無を確認する。異常が出ても台帳を自動修復・追加支給しない。

### 手動確認（本番2アカウント）
- ローカルデモとブラウザE2Eに加え、二人で同じ100 KP対局を完了する。終了時に双方の残高、台帳の `duel:stake:*` と `duel:payout:*`、表示損益を突合する。
- 接続を切って応答を失わせた場合、前回と同じ操作IDで結果を確認し、追加の招待や賭け金移転が生じないことを確かめる。
- 引き分け・投了・タイムアウト・別端末の同時操作・再接続・過去履歴ページングを確認する。
- 本PRではテスト用の認証済み2アカウントがないため、実際のKP消費を伴うこれらの確認はまだ実施していない。

### 変更しない範囲
指令の条件・報酬・費用、参加者のDiscord ID、`kp_directives`、既存のKPトリガー、D1のテーブル構造、定期バッチの頻度には手を加えていない。
