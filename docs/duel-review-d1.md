# 決闘6モード 品質確認・D1保護
2026-11-07 改善計画（PR #365）

## 今回の対応
- 進行中ルーム優先表示、6モードの実動デモ、iPhone向け五目並べ操作は既存のPR #360〜#362の内容を維持。
- Hit & Blow: 入力中の数字を画面再描画後も維持（ブラウザ内の一時メモリのみ）。40手目で正しく終了。推理履歴を最大40件表示。
- オセロ・五目並べ: 前回受信した盤面との差から「新しく置かれた石」が一つだけ確定できた時に限り、直前の着手を強調。最大12手の**端末内履歴**を表示。再起動やオフライン中の手は復元できないため、全対局履歴とは呼ばない。
- ブラフダイス: 宣言の初期値を直前より強いものとし、入力できない選択肢を無効化。10個・6の目の後は疑いのみ。
- ポーカー: 公開された5枚から役名を計算して併記。勝者・引き分けの判定はサーバー側の元の関数を継続使用。
- 対戦一覧: サーバーがすでに返している直近最大20件から対戦成績、相手別の成績を集計。追加クエリなし。
- 賭け金: 差引損益を表示。50,000 KP以上の申し込み・承認はアプリで2回確認。サーバー側の100〜100,000 KP制限・残高照合・一意な操作IDは維持。
- 手番切替: 対戦画面を見ている間のみ画面内に通知（Discordへの通知投稿はしない）。残り時間はブラウザだけで毎秒表示。
- 復帰: 非表示タブでは自動更新せず、復帰後に最後の取得から6秒以上経過していれば再取得。対局中10秒、招待あり20秒、その他30秒を目安にポーリング。
- 各ゲームを初めて遊ぶ人向けに一行の遊び方説明を追加。

## D1保護
1. 新テーブル・インデックス・監査ログ・書き込み・定期スキャンを追加しない。KP台帳と対戦の原子的トランザクションを変更しない。
2. 対戦の着手履歴・成績・通知・タイマーは、すでに返却済みのJSONとブラウザのメモリのみから作る。
3. 期限切れの精算は既存の5分ごとの処理に任せ、ブラウザから勝手に再決済しない。
4. D1使用量の実測が必要な場合はCloudflareメトリクスで確認する。PRの時点では本番削減率は未計測。

## 実機テスト（2人それぞれのDiscordアカウントが必要）
本番で無断のKP消費を行わないため、本PRはユーザー2人の実口座で賭けを確定していない。ローカルデモ(`duel-demo.html`)は本番API・D1に接続しない。ブラウザテストと別に以下を実施する。
1. 2つの別アカウントで同一サーバー内のKP口座を接続し、お互いが候補に出ることを確認（名古屋・小林・千葉ゆうや・VDK・藤村・石原の名前が正しいことも確認）。
2. オセロ/五目並べ/四目並べ/Hit & Blow/ブラフダイス/5カードポーカーをそれぞれ100 KPで申し込み・承認・着手し、端末を閉じて再参加する。
3. 対戦ごとに両者の表示が一致し、秘密の数字・ダイス・手札が相手へ漏れないこと、勝者が合計200 KPを受け取り、負けた側は100 KPを失い、引き分けでは双方に返ることを照合。
4. 期限切れ/投了/重複タップ/通信切断後の再送で二重決済しないことを確認。50,000 KP以上は実KPを使わずUIの二段階確認に限定する。
5. 失敗時は新規招待・決済を続けず、口座明細と既存のKP台帳を管理者が照合する。

## 範囲外・制約
- 本番Discordへの「手番DM通知」は追加しない（不要な通知・APIアクセスを避ける）。
- 過去30日超の全着手履歴や永続統計DBは追加しない。今回は既存の20件と端末で確認した手のみ。
- 実D1に対する定期異常スキャンは新設しない。既存の対局E2Eテストでゼロサム決済・冪等性・残高不足・重複確定をチェックする。稼働後はCloudflareのD1メトリクスとKP台帳の管理確認で補完する。
- 指令の費用、達成判定、通知、KP付与、対象者、`kp_directives`の行には一切触れない。
