# 雀魂の友人戦・KP移動（試験導入）

## 試験と有効化
1. PRのCI合格後にmainへ取り込み、GitHub Actionsの「Mahjong friend-match scan」を手動実行（probe_only=true）。これは友人戦履歴の読み取り試験のみであり、WorkerやKPに書き込まない。
2. probe_only=falseで単発の実取得を検証する。Workerの MAHJONG_FRIEND_SETTLEMENT_ENABLED が未設定なら、対局を検出してもpreview扱いでKP移動はない。
3. GitHubリポジトリのVariablesで MAHJONG_FRIEND_SCAN_ENABLED=true にすると、30分ごとにスキャンする。最新の最大20件から未処理5件を取得する。falseまたは未設定ならスケジュール実行しない。
4. 対象者のDiscord IDと雀魂IDをリンクさせ、正常に自動認識できることを確認後、Workerの MAHJONG_FRIEND_SETTLEMENT_ENABLED=true で新規対局のみ自動精算を有効にする。過去のpreview分はさかのぼって精算しない。

## 対象と精算
- 友人戦 category=1、部屋番号あり、AIなし、3人/4人、東風/半荘、終了後6時間以内に限定する。
- 全参加者の雀魂アカウントIDが一意にDiscord登録メンバーと紐付くことを必須とする。未登録やCPU混入は移動しない。
- 四麻半荘は +200/+50/-50/-200、四麻東風は +100/+25/-25/-100、三麻半荘は +150/0/-150、三麻東風は +75/0/-75 KP。旧案の約3分の1〜4分の1に縮小し、合計増減は0。
- 参加者の残高が不足すると全員の移動を中止する。借KP、遺物、運補正は適用しない。
- 対局UUID単位で処理済みを記録し、KP台帳の行も一意にする。D1の1回のバッチに全参加者の移動をまとめ、部分処理を防止する。
- 対局結果は既存HMAC認証（5分有効期限）を利用して受け取る。段位戦の報酬処理とは分離する。

## 制約と監視
- 認証に使用する雀魂アカウント本人が参加した友人戦しか自動発見できない場合がある。第三者の履歴の全件監視は行わない。
- 非公開の雀魂内部APIに依存するため、仕様変更・利用規約やアカウントへの影響を検証する必要がある。
- GitHub Actionsの公開ログには牌譜UUID、ユーザーID、認証情報を出さない。D1の kp_mahjong_friend_games と kp_ledger.kind=mahjong_friend の件数を監視する。
- 試験用に検出された試合はpreviewとして保存し、後から有効化しても精算しない。
- 意図的な対局結果操作によるKPの移転は技術的に完全防止できないため、参加メンバー全員のルールへの同意が前提である。
