# KESO COACH PR1-B：本人限定の目標登録

承認済み設計 #612 のPR1-Bです。PR1-A #613 の本人対応と既存KPセッションを使います。

## 保存・認可

- コンペ目標ランクと次の試合の行動を、各1件取り組み中にできます。任意の目標日、最大3手順、試合後の確認方法を登録・編集できます。
- `coach_goals` は `coach_profiles` の人物に複合外部キーで紐づきます。神戸の2アカウントは同じ目標を使用します。試合・位置・KP台帳へ保存しません。
- GET/POST `/api/kp/coach/goals` とGET `/coach/me`・`/coach/members/status` は、セッションから本人を解決して目標を返します。所有者を本文から指定できません。他人の目標IDによる更新は404です。共有要約へ目標を含めません。
- UUIDによる新規送信の再試行とversionによる更新競合検出があります。競合時は409で入力を残し、明示的な破棄・再読込で最新内容を確認します。
- 正しい公式ランク、Unicode文字数、UTF-8全体4 KiB、実在日付、未知フィールドをサーバーで検証します。本文はプレーンテキストで描画します。
- 状態は取り組み中／本人が達成を記録（自己申告）／終了です。終了した目標は読取専用です。期限経過による自動削除・失敗認定はありません。現在ランクや診断ロジックを変更しません。

## 読み取り・運用

初回は既存のmeレスポンスへ同梱し、追加HTTP要求やポーリングを行いません。目標の読取は、本人の進行中最大2件と履歴直近20件を索引で絞る1クエリです。APIでページを開くたびのDDLや自動作成を行いません。入力中の書き込みもありません。

保存は所有行の取得とINSERTまたはCAS UPDATEです。新規競合時だけ確認の再読取があります。SQLiteの実行計画で履歴の専用索引を確認しています。クエリ数を実際のD1 rows_readと同一視しません。本番監査は目標本文を取らず、件数・孤児・状態異常・進行中の重複・rows_readだけを記録します。

専用ensureスクリプトで0011だけを加算適用します。過去のmigration一括適用・本番目標の初期投入・KP書き換えは行いません。Henrikへの追加取得はありません。
