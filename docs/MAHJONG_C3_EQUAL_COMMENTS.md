# 等しいbot：牌譜に基づくひと言

開発ブランチ `feat/mahjong-review-sanma` / PR #377 の仕様。未マージ・未配置。
検証対象の完全SHA、実牌譜の確認範囲、自己採点は [開発引き継ぎ](MAHJONG_REVIEW_DEVELOPMENT_HANDOFF.md) を参照。

## 投稿と判断の範囲

順位・KP・遺物・主な和了/役・メンバー別の成績/煽り・メンション・既存引用を維持し、実際の打牌に言及する関西弁コメントを1〜2件追加する。食い替えなどの不正な打牌を推奨しない。
本文にモデル名や `c3` は出さない。実在人物の発言の引用ではなく、botの創作コメント。

| 対象 | 実際に計算するもの | 判断しないもの |
| --- | --- | --- |
| 四麻 | 本人視点のMJAI履歴を元モデルへ実入力。推奨/実打牌を手牌と合法maskへ照合 | 初期親ツモが不明な親本人、自家立直後の強制打牌/未検証の槓、未知の特殊ルール |
| 三麻の形 | 専用牌構成で通常形/七対子/国士の向聴数、既知牌を引いた受け入れ、ドラ/赤の保持 | 序盤門前等の条件外、手中の北を抜く選択、テンパイ、着順/攻守全般 |
| 三麻の守備 | 単独リーチ者の河にある本人の現物。遠い手などに限定 | 他家全員への安全、危険度の数値、押し引き期待値 |
| 三麻の打点 | ポン/大明槓・加槓/暗槓を含む本人のテンパイ候補ごとに役/符・表ドラ・赤・抜きドラ・風牌を計算。待ち枚数と条件付きツモ打点を比較 | 役満/数え役満の比較、ロンのフリテン判定、北抜き/槓/リーチ行動そのものの推奨、オーラス/極端な点差での順位期待値 |

三麻は四麻モデルを流用しない。形/現物は独自ルール計算、役/符はMITの `mahjong==2.1.0` を使用する。**学習した三麻AIではない。**

打点は「ツモ和了（門前/副露を区別し、宣言打牌ならリーチ/ダブルリーチ後ツモ）・ツモ損・本場と供託抜き」の試算。宣言していない未来のリーチ・一発・裏ドラ・海底・嶺上は仮定しない。
未知の待ちが減らず、候補の最低打点が実打牌の最高打点を1000点以上上回る場合など、明確な差だけに言及する。和了確率やゲーム全体の期待値とは呼ばない。

表示例（人工の局面）：

> 「けそ、東1局の8打目の2pですかぁ。対小林のリーチだけ考えるなら、僕は現物の9mも考えますねぇ」
>
> 「東1局の2打目、けそは2sですかぁ。僕は5sも見たいですねぇ。見えてへん待ち牌は7枚、門前ツモ・ツモ損で、本場と供託を抜いた試算で6000点ですわ」

新レポートは鳴き後にも曖昧にならない「N打目」を使う。旧四麻v1/三麻v1/v2の互換維持。新バージョンを旧Workerへ送った場合は追加コメントだけを拒否し、旧本文/KPを保つ。

## 復元・非公開情報・負荷

1. 既存Actionsで牌譜を取得し、その打牌時点の自分の手牌/ツモと公開河/副露/北/リーチ/ドラ/点数/親/本場/供託を復元する。
2. 他家の非公開手牌/ツモ、山、裏ドラ、未来情報はモデル/手牌計算へ渡さない。公開された赤牌は、復元検証用の非公開在庫とは別に管理する。
3. 各席を先に1件ずつ確保し、余り枠で根拠のある称賛/代替案を選ぶ。最大4findingだけを既存の署名付きsummaryへ含める。生の手牌/河は追加DB保存しない。
4. 従来本文・解析・末尾引用を保存して配送する。通常は1投稿のcontent<=1900とembed合計<=6000へ収める。さらに長い場合だけ全パートをD1.batchで原子的に登録し、固定IDで再登録を重複させない。
5. 既存KP式・遺物・報酬台帳は変更しない。通常の新規D1クエリ/テーブル/cronは0。例外長文の追加投稿数だけINSERT行数が増える。

最大1worker/バッチ、45秒/回・合計90秒。モデルは対象局面がある時だけ遅延起動し、既存SHA付きキャッシュを利用する。
三麻の手牌計算は1対局最大12局面/1席4局面、入力256KiB、自己終了7秒・呼出側8秒。Pythonには資格情報・継承環境変数・名前・ID・全牌譜を渡さない。
モデル/依存取得・計算の失敗は任意コメントだけ省略し、従来機能を継続する。モデル資材のライセンス/ソースは [資材の取り扱い](../services/valorant-results/scripts/c3-vendor/README.md)、手牌計算のMIT通知は [同梱ライセンス](../services/valorant-results/scripts/sanma-vendor/MAHJONG_LICENSE.txt) を維持。

## ローカル検証

Node 24以上とPython 3.12を使用し、`services/valorant-results` で実行する。

```sh
npm ci
python3 -m venv .venv-mahjong
.venv-mahjong/bin/python -m pip install --no-deps --only-binary=:all: --require-hashes -r scripts/sanma-requirements.txt
SANMA_PYTHON="$PWD/.venv-mahjong/bin/python" npm run check
npm run build
```

Python設定がない場合は打点比較だけを省略する。関係するソース/依存/テストを変えたCIは固定依存を準備し、実計算テストも実行する。

## 設定と本番確認

- 四麻の既存設定 `MAHJONG_EQUAL_REVIEW_ENABLED` は維持。`false` で任意推論を停止。
- 三麻はリポジトリ変数 `MAHJONG_SANMA_REVIEW_ENABLED=true` の時だけ有効。本作業では変更していない。
- 既存 `Mahjong paipu fetch` の手動 `c3_probe=true` は実モデルだけの検証。雀魂/Discord/KP/D1へアクセスしない。
- 手動 `review_audit=true` はSELECT1回、直近rowid64行内から最大12件を読み、最大2対局を再取得して匿名検証。取り込み/支給/Discord送信/DB書き込みなし。通常cronでは診断しない。
- 配置時は先に新レポートを検証できるWorkerを配置・確認してから三麻を有効にする。トークンの再作成やDB migrationは不要。
- 実牌譜再取得、モデル/手牌計算の実行、独立正解との照合、Discord本番送達はそれぞれ分けて記録する。実Discord送達を模擬送信の成功で置き換えない。

固定IDはキューの重複登録を防ぐ。既存Webhookの応答喪失や、KP処理とキュー登録の間のクラッシュまで完全なexactly-onceを保証するものではない。

## 配送確認の手動モード

- `delivery_audit=true`: ログイン/モデル/依存準備なしで、保存済みレポートと既存投稿の配送件数だけを1 SELECTで確認する。本文・UUID・名前はログへ出さない。
- `delivery_probe=true`: 所有者限定。人工牌譜の三麻/四麻を実計算し、「人工牌譜・KP支給なし」の検証を既存キューへ1通登録する。同じrelease SHAは再送しない。1行のINSERTと最大5回の主キーSELECT以外にDB変更はない。
- 解析を変更した配置後は既存dispatch資格情報でread-only確認を起動できる。配置commitに明示的な`[mahjong-review-probe]`を含む時だけ、上記の検証投稿を選べる。通常の配置やcronで人工投稿を繰り返す仕組みではない。
