# 等しいbotへのc3牌譜検討コメント（第1段階：表示側）

## 目標

既存の順序「アカンbotの速報 → 等しいbotの牌譜検討」を変更しない。
等しいbotの**同じ牌譜投稿**に、局・本人の巡目・捨て牌・c3が選んだ牌を添えた短いコメントを入れる。

等しいbotに表示する文面例（以下はダミーの対局で、実際の検討結果ではない）：

- 指摘：「けそ、東1局の4巡目の6pなあ。僕はここで3p切りますけどねぇ〜。ちょっと惜しい気がしますわ」
- 褒め：「小林、東3局の9巡目の東ねぇ。いや、僕もそれ切りますわ。これはええと思いますよぉ〜」

投稿上の見出しは「松本等しいのひと言」。利用者向けの文面・注記にエンジン名を出さない。自然な関西弁、一人称「僕」で、毎回同じ口癖ばかりにならないよう複数の短い言い回しを使う。

このセリフは等しいbot用に生成した創作文であり、実在人物の発言の引用ではない。

## 今回の実装範囲

- 既存の署名付き `/api/mahjong/paipu/summaries` が受け取るサマリーに、任意の `c3` フィールドを追加。
- `c3` は固定モデル版 `c3-v1.0-observation-1`、元牌譜UUID、四麻、参加者席番号、局番号、巡目、実打牌、推奨打牌を検証。
- 既存の順位・KP精算・主な和了・メンバー別の成績と煽り・末尾の引用文を最優先する。従来の投稿全文がDiscordの1900文字枠に収まる時だけ、空き文字数に応じて新コメントを最大2件挿入する。枠が足りなければコメントは省略し、従来の投稿を1文字も変えない。
- コメントを最大2件までに制限し、登録済みの登場人物以外を評価しない。見直し候補と一致した好判断が両方あれば、原則として批評1件・称賛1件を優先する。実打牌と推奨打牌が一致した報告も受け入れる。
- 未検証、形式不正、三麻、未提供の報告は従来の投稿を維持。既存KP処理・監視・D1クエリ・Discordメンション数を変えない。
- 入力文の自由記述は一切信用せず、牌名は固定構文、表示文はKESO側で生成する。
- **今回のPRだけではc3の推論処理はまだ呼ばない。実際のコメントは、認証済みの収集処理がc3の確認済み結果を送信するまで表示されない。**

## 次段階：元のc3モデルを動かす

1. `mahjong-paipu.mjs` が対局記録のprotobufを取得した際に、`RecordNewRound` / `RecordDealTile` / `RecordDiscardTile` / リーチ・副露・槓等を復元する。**巡目は全体のアクション数ではなく、各席のその局の打牌回数**として数える。
2. c3の観測器には、打牌判断前の公開牌、本人の手牌・ツモだけを提供する。他家の配牌・隠れたツモ・未来の情報を入れない。
3. 元c3の実推論から合法な打牌候補を得る。実打牌との差をM-LEAGUE Manager側の改善候補判定と同様、守備・手の進行・打点など公開事実から検討する。違いだけでミスと断定しない。三麻は未対応として除外。
4. 対局を読んだ**同じGitHub Actionsの実行中**に解析を終えて、牌譜サマリーと一緒に送る。投稿を先に出した後からコメントを捏造して追加しない。C3取得失敗時は既存投稿を通常どおり送る。
5. KESO PLAYの公開GitHubへM-LEAGUE Managerの非公開ソース・秘密情報を無断コピーしない。モデルの配信約44MB、ブラウザ/Node性能、c3重みMITとMortal観測器AGPLの配布要件を確認する。
6. C3出力を同じ牌譜上の該当打牌と突き合わせ、役牌・赤牌・ツモ切り・副露・リーチ・点棒変化を実牌譜でテストする。本番投入前に50局面以上の再現・二重投稿防止の検証を行う。

## 原則

- 「東1局4巡目」という根拠がないまま、自然なセリフだけ生成しない。
- 投稿では「僕なら」「僕もそう切る」と話し、モデル名・モデルによる提案であることを直接言わない。
- 推奨との不一致だけで失着・放銃確率を断定しない。単なる一致を過大な実力評価にしない。
- 松本等しい本人の実発言を引用したものではない。botの創作コメントである。
- C3のQ値を放銃率、期待打点、失着点数として表示しない。
- 元の等しいbotの文章と本人ごとの口調設定を維持する。
- KP、D1への加算・減算、および友人戦の別PR #368には影響させない。
