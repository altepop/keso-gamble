# 等しいbot：牌譜に基づくひと言

開発ブランチ `feat/mahjong-review-sanma` / Draft PR #377 の仕様。未マージ・未配置。
最新の検証、自己採点、再開手順は [開発引き継ぎ](MAHJONG_REVIEW_DEVELOPMENT_HANDOFF.md) を参照。

## 投稿と解析の範囲

順位・KP・遺物・主な和了/役・メンバー別の成績/煽り・メンション・既存の引用を維持し、根拠がある1～2件の短い関西弁コメントを追加する。
プレイヤー向け本文に解析モデル名や `c3` は出さない。実在人物の発言の引用ではなく、botの創作コメント。

- **四麻:** 元モデルを実推論。本人の配牌/ツモだけを残したMJAI履歴を作り、他家立直・チー/ポン・非立直時の各種槓以降も対応。実打牌と推奨牌は復元手牌と観測器の合法maskへ照合する。初期親ツモが不明な親本人、自家立直後の強制打牌/合法性未確認の槓、未知の特殊ルールは除外。
- **三麻の形:** 四麻モデルを使わず、専用牌構成の向聴数/受け入れ/ドラ保持数に基づく限定した比較。序盤門前など確かめられる場面だけに絞る。
- **三麻の守備:** 1人だけがリーチ、本人は3向聴以上などの条件で、その相手の河にある現物を提示する。他家全員への安全や放銃確率を断言しない。
- **三麻の打点:** 翻/符を入力とした得点算術と実和了での校正まで。手牌から役/符を判定して打牌を推奨する機能はまだない。この算術を根拠に完成済みの戦術AIと呼ばない。

表示例（架空の対局）：

> 「けそ、東1局の8打目の2pですかぁ。対小林のリーチだけ考えるなら、僕は現物の9mも考えますねぇ」

新レポートでは鳴き後にも曖昧にならない「N打目」を使う。四麻v1の旧レポートは互換維持。新しい四麻v2/三麻v2を旧Workerへ送っても追加コメントだけが拒否され、従来の本文/KPは保たれる。

## 共通経路と障害時の動作

1. 既存Actionsが雀魂から牌譜を取得し、公開/本人の履歴を復元。
2. 四麻はモデル、三麻は決定的なルール計算へ渡す。他家の非公開手牌/ツモ、壁、裏ドラ、未来情報を判断に使わない。
3. 各席1件ずつを先に確保し、余り枠で本物の称賛/代替案を残す。人数に関係なく最大4finding。
4. 既存の署名付きsummaryでWorkerへ送る。任意コメントは最大2件、1,900字に入らなければ旧本文を優先。従来本文自体の長文分割は未対応。
5. 既存の冪等な投稿/精算処理へ接続。再送で投稿/KPを増やさない。新しいD1クエリ/テーブル/cronは追加しない。

推論は最大1worker/バッチで遅延起動し、45秒/回・合計90秒まで。対象がなければモデルを読み込まない。取得/初期化/推論が失敗しても従来の牌譜/KP処理を続ける。巨大モデルはGitへ保存せず、既存の固定SHA付きキャッシュを使う。ライセンス/対応ソースは [資材の取り扱い](../services/valorant-results/scripts/c3-vendor/README.md) を維持。

## 設定と診断

- 四麻の既存設定 `MAHJONG_EQUAL_REVIEW_ENABLED` は維持。`false` で任意推論を止め、従来の投稿に戻せる。
- 三麻は `MAHJONG_SANMA_REVIEW_ENABLED` が文字列 `true` のときだけ有効。未設定・無効のままで、本PRが未完成のうちは有効化しない。
- 既存 `Mahjong paipu fetch` の手動 `c3_probe=true`: 実モデルだけを検証。雀魂/Discord/KP/D1へアクセスしない。
- 手動 `review_audit=true`: 直近rowid64行内をSELECT1回、最大2対局を再取得して匿名検証。取り込み/KP/Discord送信/DB書き込みなし。通常の定期実行では診断しない。
- 診断ログは人数/件数/計算一致と固定エラーだけ。実牌譜・名前・ID・トークンはログ/成果物へ出さない。

実牌譜を取得して構造を確認したこと、人工履歴で実モデルを実行したこと、独立正解との照合、Discord送達は区別する。詳細な検証範囲は引き継ぎ文書とPR本文に残す。
