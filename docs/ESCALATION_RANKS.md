# エスカランクの確認

Discordでは次のコマンドで確認できる。ランク照会で残高・台帳は変化しない。

| コマンド | 内容 | 表示範囲 |
| --- | --- | --- |
| `/esca rank` | 自分のランク・RR・認定進捗・今ACTの最高・前ACTの記録 | 本人のみ |
| `/esca rank user:@メンバー` | 同じサーバーのメンバーのランク情報 | 呼び出した本人のみ |
| `/esca ranking` | 今ACTの認定済み上位10人。同RRは同順位 | チャットへ公開。メンション通知なし |

いずれもDiscordの署名検証済みInteractionsからのみ利用する。内部レート・口座残高はランクカードに含めない。認定していないメンバーも口座を作らず未認定として表示する。

Activityは「稼ぐ」の先頭に、ランク専用カードを表示する。各ランク・段階に対応した公式デザインの画像・RRゲージ・認定のステップ・戦績・最高ランク・前回変動幅と、詳細内の順位・過去ACT・全ランク一覧を確認できる。認定中は前ACTのランクを表示し、初回KDプラスの100RRは通常補正と分けて表示する。

## 画像

`assets/escalation-ranks/` はRiot GamesのVALORANTランク画像26種（8ランク×Ⅰ・Ⅱ・Ⅲ＋レディアント＋未ランク）。未認定の「？」もVALORANTの元画像です。画像はリサイズ・描き直しをせずPNGのまま保存し、ActivityとDiscordの両方から同じファイルを使う。画像中にユーザーID・認証情報・内部レートは含まない。

画像の取得元・固定コミット・SHA256・元の画像寸法は `SOURCE.json` に記録する。画像の権利はRiot Gamesに帰属し、コードのライセンスとは区別する。利用方針の参照先は https://www.riotgames.com/en/legal 。取得元の公開ミラーや非公式表記だけで、あらゆる用途の利用許諾を保証するものではない。KESOのランク表示がVALORANT本体のランクではないことと非公認であることを画面・カードに明記する。

古いオリジナル紋章と生成スクリプトは削除し、公式画像を誤って生成物で上書きしない。Activityのキャッシュ版数は画像の内容も含めて計算する。表示に音声・canvas・WebGLは不要。

## Discordへの登録

`KP_COMMAND_VERSION`（v28：/esca分離・ラジオ/アルバム共存版）を更新し、既存のVoice Gatewayの差分登録に反映する。さらに既存Client Secretによる `applications.commands.update` の短命トークンで、10分ごとの既存cron内から `/esca` の新規登録と `/kp` の旧ランク項目除去だけを行う。`/kp ranking` はKP残高用のまま。`/death`・`/valo`・クイズOAuth・ActivityのEntry Pointは変更しない。新しい秘密値の入力は不要。

`GET /api/discord/rank/status` で、期待するコマンド版数と登録済みマーカーを確認できる。トークンや秘密値は返さない。Discordが登録内容を確認できた場合だけマーカーを保存する。登録直後はDiscordクライアントの候補更新に時間が掛かることがある。

初回3試合／ACT更新1試合／エピソード更新3試合、報酬との関係や内部計算は `VALORANT_REWARDS_REVIEW_20261111.md` を参照。

## 初回認定のボーダー（2026-11-14改定）

初回認定は3試合のまま、勝利1回あたりの認定ポイントを200から175に変更した。成績補正（合計最大5）と全3試合KDプラスの＋100は据え置く。ランク境界は100ポイントごとで変更しない。

| 初回3試合の勝数 | 通常の認定結果 | 全3試合KDプラス |
| --- | --- | --- |
| 0勝 | アイアンⅠ（0） | アイアンⅡ（100） |
| 1勝 | アイアンⅡ（175） | アイアンⅢ（275） |
| 2勝 | ブロンズⅠ（350） | ブロンズⅡ（450） |
| 3勝 | ブロンズⅢ（525） | シルバーⅠ（625） |

表は成績補正0の結果。**変更前に確定したランク・RR・内部レート・過去ACT・KPは再計算しない。** ACT更新・エピソード更新・認定後の毎試合RRとランクシールドも変更しない。D1の旧シールド版マーカーを保持し、移行時に消費済みシールドを補充しない。

## 毎試合のRR（per-match-v2）

認定後は勝ち＋20／負け−20を基準に、個人成績で−10〜＋10を加算する。最終変動は勝ち＋10〜＋30、負け−30〜−10 RR。100 RRで1段階。下限0では実際に引けた分だけを表示する。

成績補正はKD（±8）、同じチームの他プレイヤーのキル中央値との差（±3）、アシスト（−1〜＋2）の合計を±10へ制限する。KDがプラスでも15キル未満では加点を減衰させ、低キル・低デスだけで上限を取れない。本人のK/D/Aが欠ける場合は中立の0。他メンバーが不足・重複している場合はチーム比較部分だけ0。監視で取得済みの同じ試合データを使い、追加のAPI取得はしない。

初回3試合・ACT更新1試合・エピソード更新3試合の認定計算は継続する。確定済みRR・最高ランク・過去ACT・KPは再計算しない。旧シリーズの未確定勝敗は次の試合で解消し、その試合から毎試合評価する。旧キューのイベントには新しい成績補正が入っていないため0として扱う。

既存DBでは成績補正列の追加とトリガー更新を自動実行する。トリガー入れ替え・スキーマ完了マーカーは同じD1 batch内。失敗時に旧トリガーを保持し、再試行できる。完了後はコールドスタート時の固定キー照会とメモリー内キャッシュだけで初期化を省略する。試合ごとのD1往復・保存行数は増やさず、既存の一意キーで再評価を防ぐ。

## ランクシールド（rank-shields-v1）

ブロンズ〜イモータルのⅠには2枚。RRが残っている状態で負け、計算結果が次の段階へ下がる場合は、現在の段階の0 RRで止める。この時点では消費しない。Ⅰの0 RRで負けたら1枚消費して0 RRを維持し、2枚使った後の次の敗北で降格する。敗戦の内部レートは保護中も減少する。隠れた借RRを作らず、降格時にもその1試合分だけ減算する（前段階70〜90 RR）。

同じⅠでの勝利では補充しない。別の段階から昇格・降格でⅠに入った時だけ2枚へ戻す。Ⅱ・Ⅲとレディアントにはシールドなし。アイアンⅠはこれ以上下がらないためシールド対象外。初回・エピソード認定でⅠになれば2枚、同一エピソードのACT認定は枚数を引き継ぎ、同じⅠのままなら補充しない。

既存のⅠにも導入時に一度2枚付与する。過去のRR・KP・勝敗は変えない。シールド列追加後、初期付与・トリガー交換・完了マーカーは同じD1 batch内で確定する。付与にはDB上のマーカー条件を使い、同時に起動した別isolateが消費後に再付与することを防ぐ。per-match-v2の既存マーカーも維持し、古いisolateによるトリガーの巻戻しを防ぐ。追加の試合レシートや試合ごとのDB往復は不要。

公式の[ランクシールド説明](https://playvalorant.com/ja-jp/news/game-updates/valorant-patch-notes-10-01/)と[現在のRR説明](https://support.riotgames.com/en-us/valorant/gameplay/rank-rating-rr-for-iron-through-ascendant-ranks)を参考にした。KESOの相手補正・認定試合数・通常RR計算はVALORANT公式と完全一致しない。案内は「コンペと同じ感覚のランクシステム」とする。
