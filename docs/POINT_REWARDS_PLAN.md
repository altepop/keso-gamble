# 試合と通話のKP

自動支給はまだ有効にしていない。金額・開始日・通話の対象条件を決めた後で本番をつなぐ。ブラウザーのデモ残高はサーバー口座へ持ち込まない。

## 金額案（未稼働）

ユーザーの基準は「コンペのハードルは高く、チーデス・エスカレーションは低い。コンペだけ勝利ボーナスを高めにし、3連勝程度で指名に届かせる」。コンペへの指名は既存デモの2,500 KPを基準に据え置く。

コンペは1勝900 KP（参加300＋勝利600）。ゼロから2連勝で1,800 KP、3連勝で2,700 KPとなり、1件指名して200 KP残る。これは追加の連勝手当ではなく1試合ごとの勝利報酬による到達目安なので、勝利が連続していなくても獲得したKPは残る。チーデスとエスカレーションは1勝45 KP（参加30＋勝利15）に抑える。この2モードだけで指名に届くには56勝分が必要。

以下は配分案で、自動支給の設定やブラウザーのデモ報酬にはまだ反映していない。

| モード | 参加KP | 勝利ボーナス |
| --- | ---: | ---: |
| コンペ | 300 | 600 |
| アンレ | 200 | 100 |
| スイフト | 60 | 30 |
| スパイクラッシュ | 40 | 20 |
| チームDM | 30 | 15 |
| エスカレーション | 30 | 15 |
| レプリケーション | 60 | 30 |
| デスマッチ | 完走確認後50 | 0 |
| カスタム | 保留 | 保留 |

通話案は5分で5 KP、1日240 KPまで。2人以上の通話を対象とし、AFKチャンネル・Bot・スピーカーミュート中・接続が確認できない時間は除外する。まだユーザーが確定した運用値ではない。

## デスマッチ

ユーザー指定は「システム上可能なら完走のみ支給」。Henrik公式OpenAPI v4のプレイヤーにsession_playtime_in_msがある一方、本人の完走・途中退出を直接示すフラグは確認できなかった。試合全体のis_completed、参加時間の長さ、キル数だけで完走と断定しない。現段階では支給を保留する。実際の完走・途中退出の応答を比較し、確実に区別できる情報が見つかるまで金額を支給しない。

## 本番で必要な接続

1. Discord認証済みの本人とサーバー口座を接続する。デモ残高と混ぜない。
2. 既存の口座migration0005の未適用を確認する。現行reward_eventsは3モードだけを許可しているため、全モード用の追加migrationが必要。
3. 速報の元データから支給イベントを保存する。通知の成功・失敗と切り離した再試行、試合ID＋PUUIDによる一度だけの支給を実装する。未知の勝敗には勝利ボーナスを付けない。
4. 台帳で支給が確定してから速報へ獲得KPを追記し、Activityは同じ口座を読む。通知本文の解析や画面のタイマーは支給根拠にしない。
5. 通話の入退室はDiscord GatewayのGUILD_VOICE_STATESから受ける。現在の速報BotはHTTP型で、この接続は未実装。常時接続するBotが必要で、録音・文字起こし・音声の解析は不要。接続断の期間は推測で加算しない。
6. 支給はサーバーの同一トランザクションで進捗と台帳を更新する。退室・再入室・同じイベントの再送で二重支給しない。

src/reward-readiness.tsはモード判定・保留と通話の金額計算だけを用意している。監視・Gateway・HTTP・口座支給にはまだ接続していない。この計算関数だけでは自動支給は始まらない。
