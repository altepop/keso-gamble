## 実装した受信契約

`POST /api/kp/loop/reward` は信頼されたLOOPサーバーから呼ぶ。
Activityセッションだけでは支給しない。ブラウザー向けCORSは追加しない。

```json
{
  "kind": "loop.milestone.completed",
  "version": 1,
  "guildId": "対象guildのID文字列",
  "discordUserId": "サーバーで本人確認したID文字列",
  "milestone": "chapter.1",
  "evidenceId": "認定記録のID",
  "completedAt": 0
}
```

`completedAt` はUnixミリ秒（例の0は実際には無効）。本文上限4,096バイト。
`X-Loop-Time` に送信時刻のUnixミリ秒（13桁、許容差5分）、
`X-Loop-Signature` に `timestamp + '.' + 実際のJSON本文` のUTF-8をEd25519署名した標準Base64を指定。
再送時は同じ達成内容で送信時刻・署名を更新する。専用鍵を使い、秘密鍵はLOOPサーバーのみ、公開鍵はKP側に置く。
署名は送信元を確認するだけで、プレイ内容を認定するものではない。
金額は受信側の許可表で決め、リクエストの金額は使用しない。
guild不一致、未知の達成、開始日時より古い達成、未来の達成を拒否。

Workerの `KP_LOOP_REWARDS_CONFIG` に以下のJSONを設定する（現時点では設定しない）。

```json
{"enabled":false,"startsAt":null,"publicKey":"","rates":{}}
```

有効化にはenabled=true、正のUnixミリ秒の開始日時、SPKI公開鍵のBase64、
達成ID→正の整数KP（最大1,000,000）の許可表が必要。不正・欠損設定は支給しない。
テストの金額は運用値の承認を意味しない。

`kp_loop_events` の一意キーはguild＋Discord ID＋達成ID。
セーブ枠・周回・端末・日時・設定版・金額を変えても再加算せず、初回の確定金額を返す。
イベント→台帳→残高はD1 batchとトリガーで同一トランザクション。台帳失敗なら口座作成も含めロールバック。
VALORANTの4人以外にも認定済みDiscord本人の口座を作れる。履歴は「KESO LOOP」と表示。

## LOOP側の接続コード

https://github.com/altepop/keso-loop/pull/42 （非公開repo）で、Discord本人・guild確認、
サーバー保存の進行、共有エンジンによる入力検証、章クリア確定と送信待ちの同時保存、署名配送、再試行、
本人の保存・配送状況表示まで接続した。ブラウザーのクリアフラグや資材をそのまま受け取る入口はない。
既存の端末3枠は残し、明示的に開始する報酬対象の進行を別に保存する。
通常章の初クリアのみ支給し、チュートリアルや目標を下げた挑戦では章報酬を支給しない。
実績の達成時刻は検証・保存するが、実績ごとの金額は確認中なので未支給。

テスト用DB2個と双方の実コードで、第一章5,000 KP＋第二章30,000 KPの入金と、
入金後に応答だけ失われた場合の再送でも一度しか加算しないことを確認した。
第一章は新規進行から実際にクリア、第二章はサーバー保存の終盤チェックポイントから実エンジンで検証。
これは本番口座への支給ではない。
