## 発見：P1 通知の未送信者が送信済み扱いになる
対象：`services/valorant-results/src/index.ts` の `flushNotifications`。

**症状と再現**：
`SELECT ... WHERE match_id=?` はDeath系モードの予約条件を満たさないプレイヤーを対象外とする一方、旧実装の `UPDATE notifications SET sent=1 WHERE match_id=?` は対象外の同一試合メンバーまで送信済みに変更する。
SQLiteの同一試合（通常通知1＋Deathモード通知1）で、Discordへ送る対象は通常通知1なのに2件とも `sent=1` になることを再現した。予約が後から成立した場合、Death系通知が再送されない。

**修正**（PR #376）：Discordへ実際に採用した `riot_id` 一覧だけを `sent=1` に変更する。空集合、対象ID不正、重複更新、別試合への非干渉をSQLiteで検証する。**データ構造変更・過去通知の一括操作はしない。**

**重要**：この修正は将来の取りこぼしを防ぐものであり、すでに送信済みフラグが誤って立った過去の通知を自動で再送するものではない。誤送信の可能性がある過去レコードは、個別の送信状況を確認せずに再送しない。

## 追加でチェックする順序
1. **通知の修正CI・マージ**。未送信フラグを後から勝手に戻さない。
2. **D1通知クエリの読み取り負荷の再現・最適化**。行数とクエリプランを比較してから性能修正を採用。無料枠・レスポンスに直接影響する。
3. **KP同時操作ストレス**：カジノ多重クリック、闇市同時購入、同じ馬券／株の競合、支払い失敗からの安全な再送。
4. **外部API・Discord復旧**：Steam/Unite/VALORANT/麻雀・通話で一時的に失敗しても「処理済み」扱いにならないこと。
5. **主要画面のiPhone長時間試遊**：休止・復帰・通信断・ページ更新・同時タップ。1ターンだけの操作テストに依存しない。
