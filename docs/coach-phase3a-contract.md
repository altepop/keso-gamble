# KESO COACH Phase 3-A — 実装契約と受入ケース

基準: Issue #639。Phase 2-C #637 を前提とする。これは設計契約であり、チーム機能が本番で動作することを意味しない。

## 先に満たす不変条件

- 新しいチーム参加、共有、通知はすべて初期OFF。本人の明示的な同意なしに公開しない。
- 既存の個人実施記録、メモ、個人目標本文、PUUID、match IDはチームDTOと通知DTOへ含めない。個人の記録専用コピーは既存の本人限定動線のままとする。
- 同じDiscord所有者の複数Riotアカウントはチーム人数に二重計上しない。
- 認可は毎リクエストでguild・team・owner・同意状態を照合し、他チームの存在を404で秘匿する。更新にはversionのCASを必須とし、古いリクエストの後着を拒否する。
- ロスターの同チーム所属は同一party_idの証明ではない。party_id欠損は不明であり、ソロ扱いしない。
- 分母0、確認済み試合不足、取得不能の値は「まだ分かりません」。収集対象外の位置・視界情報は「評価範囲外」。
- 共有課題はチームあたりactive最大1件。個人の実施自己申告と共有ステータスは別々に保存する。
- D1マイグレーションは加算的。索引はguild/team/updated_atを起点とし、有限LIMIT、認可前の重い集計禁止、自動ポーリング禁止。
- Discord通知は本人同意と管理者の送信先許可がともに必要。event_idとversionで重複排除し、通知失敗時も保存済み状態を巻き戻さない。
- HenrikDev以外の新規試合取得を導入しない。既存KP・決闘・KESO LOOPへ変更しない。

## パーティ指標の計算契約

確認済み同一パーティの試合のみを別集計する。勝率 = 勝利試合数 / 勝敗確定試合数。K/D = 適格なキル合計 / 適格なデス合計（ゼロ除算禁止）。各値には有効数、除外数と理由、対象期間、マップとエージェント条件を添える。練習の因果効果を断定しない。

## 実装順序

3-B本人同意・所属・CAS → 3-Cロスター指標 → 3-D共有課題・画面 → 3-E通知。各PRでテスト・CI全緑・本番デプロイ確認を別々に行う。認証済み実ユーザー2名の操作試験は人手待ちである。
