# P9.4b サーバーPvEセッション・APIの契約
- 認証済みKPユーザーだけが `/api/kp/duels/pve` を使える。既存 `/api/kp/duels` と別経路で、PvPの賭け金・KP精算・遺物に変更を加えない。
- `POST {action:"start",requestId:<UUID>,game:<6種>,level:"easy"|"normal"|"strong"}` で本人のサーバー試合を作成。本人ごとに直近24時間で更新された進行中の同時試合を最大3件に制限する。再送は同じUUIDなら同じ試合を返す。
- `POST {action:"move",session:<UUID>,requestId:<UUID>,version:<整数>,...ゲーム固有の合法手}` でサーバーが既存ルールから手を確定し、CPUをサーバーで続行する。受信した勝者・KP額・報酬値は使用しない。
- `GET ?session=<UUID>` で認証した本人の確定スナップショットだけを取得する。HTTP応答にはサーバーの`secret`列を一切含めない。本人の`ownHand`と既存ルールで公開済みの履歴だけを返す。
- D1の3表（セッション・秘密情報・操作履歴）は決闘PvE専用。操作履歴のアクションIDが一意、SQLトリガーで楽観的バージョンを検証し、操作・盤面・秘密情報を`DB.batch`の同一トランザクションで保存する。二重送信・競合で盤面を二重に進めない。
- この段階は**サーバー上で遊べる基盤APIまで**。Discord Activity内の6種目操作画面はP9.4cで接続し、PvE熟練度保存はサーバー確定終局に結び付けて別のテストで確認する。KP/遺物報酬と経済上限はP9.5まで保留する。現在のブラウザCPU練習は無報酬のまま維持する。
- 実ユーザーの本番D1対戦や認証付きテストは未実施と明記する。デプロイ成功はこの実測の代替にならない。
