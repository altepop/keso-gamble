# Muse v6 そのまま移植

## 正としたソース

`coach-prototype-v6.html` はユーザーがレビューして確定した原本です。元のCSSと本文DOMを `coach.html` の `coach-prototype-style` / `coach-prototype-template` にそのまま収録しています。テストで文字列の完全一致を確認します。600pxの最大幅、375pxでの余白、色、外部フォント指定、切り欠き、アートの位置を再設計していません。

旧画面のCSSは `.coach-existing` 内に限定し、原本のトップ画面へ上書きしません。選手選択、接続、各アカウント、比較、7タブ、練習条件、更新、コピー、収集・停止・再開は原本と同じ折りたたみ外枠へ収納しています。320pxのみ、原本のタイマー行に折り返しを補っています。

## 実データへの接続と、原本から変えた判断

- 選手名・対象アカウント・試合数は既存の個人応答を使います。「昨日の全試合を確認済み」「メインアカウント」は応答から保証できないため表示しません。
- 現在・最高ランクの2枠は維持し、応答にない値は「未取得」です。試作のDIAMOND 3 / ASCENDANT 1を実績として使いません。
- Opening Fightsのトーク欄は既存 `KesoCoachReader.trend/verdicts` の改善・強みを表示します。照準が頭の高さにあった、走ったまま撃った、という映像上の断定は作りません。根拠の2枠は既存K/DとACSです。
- 練習の選び方は変更せず、既存 `KesoCoachPractice.choose` の最大3件を同じ順にブロックへ入れます。元の課題ID、所要時間、実施条件、手順、次戦チェックを接続します。試作のP082を根拠に別の3/4/3分ドリルを自作せず、合計時間も選定結果です。副課題は同じブロックに含まれるため二重に加算しません。
- 射撃場を含む候補は既存のダイヤ帯向け表示を維持します。ミディアム→ハードの射撃テストと、プラクティスのストレイフONは別設定として説明します。
- PDCAの現在地は閲覧中の「今日の練習」です。実測の存在を確認できる試合・分析のみチェックを付け、Discord速報の配信成功は応答から検証できないため完了扱いにしません。
- Map NotesのAbyss/Summitは同名の保存済みマップ集計だけを使います。他マップの勝敗を流用しません。未取得の場合も同じアートとカードを残し、記録がない旨を表示します。ほかのマップは従来の詳細分析で確認できます。
- 数字の折りたたみは既存ACS/ADR/HS/KDを使い、公式KASTとランクは未取得を明示します。ソーヴァの記録がある時だけ同キャラの実測を表示します。Trackerのサンプル数値を本人の実測値と扱いません。
- 「この内容で実施します」、副課題のチェック、無音タイマーは画面内のみです。保存・達成認定・KP・サーバーへの送信を追加しません。元プロトタイプの確約文も、映像や練習実施を自動確認したという誤解を避ける文へ置き換えています。
- 出典は既存の保存済み戦績です。Tracker確認済みという試作の出典表記を、本番データの出典と混同しません。7画像はユーザー提供の元PNGを無加工で配置し、元ZIPとバイト単位で一致することを確認しました。

## 旧セクションの日本語確認

`legacy-coach` の固定説明文は直接敬体へ直しました。「分析の母数は完全保存済み試合だけです。」「取得元に存在しないデータは補いません。」を含みます。データ描画後にも表示境界で敬体を適用するため、初期HTMLの校正だけで動的説明が取り残されません。

ブラウザテストで旧セクションを開き、固定説明・補完状況・診断本文・FK/FD説明・ラウンド・マップ・個人・構成・品質の実描画を確認します。数値や件数のラベルを無理に文章化せず、説明文を敬体にします。観測された「死亡5.5回」を「5.5回行います」という練習回数へ変えないテストも追加しました。

新しい固定h2〜h5、カタログ見出しを追加する時は `CoachPresentation.headings` への登録が必須です。登録しない変更は単体テストで失敗します。既存の100件の元カタログ、分析・選定・認証・API・データ収集は変更しません。

## 画像比較の実行

```sh
COACH_CHROMIUM_EXECUTABLE=/usr/bin/chromium \
COACH_V6_SCREENSHOTS_DIR=docs/design/v6-review \
node scripts/coach-browser-check.cjs
```

375pxと1440pxで原本・移植画面を撮影します。画像ファイルの実ロードを確認し、主要セレクターの余白・色・フォント指定・サイズ・切り欠きが原本と一致することを比較します。データの差し替えで本文や高さは変わるため、全画面の画素完全一致を実測値の要件と取り違えません。画面はすべて人工データで、本番の本人の戦績を撮影したものではありません。フォントのロード状態も `comparison.json` に残します。

画像付き比較とCI全成功を確認するまでは、本番へ反映しません。

## 比較結果

375px・1440pxの原本/移植画面を `v6-review/` に保存しました。7画像の実ロードと、主要セレクターのスタイル一致を確認しています。外部Google Fontsの読み込みは環境制限により未確認で、両画面を同条件のフォールバックで撮影しています。詳細は `v6-review/README.md` と `comparison.json` を参照してください。
