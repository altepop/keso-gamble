# 雀魂牌譜検討：開発引き継ぎ

## 2026-11-13：判断の種類を増やす三麻v5（今回のPR）

直近の通常取得では4局141打牌を復元し、形17件・守備12件を評価したが候補0件、打点計算は対象0件だった。無効化・投稿漏れ・タイムアウトは記録されず、従来の判断カテゴリでは扱えない対局だった。今回も毎対局の講評は保証しない。

- **リーチ宣言とダマのツモ打点**：実際に宣言された門前手を、同じ手・待ち・公開ドラ・北抜きのダマ条件でも計算。比較候補の打牌が1つしかないテンパイも対象にする。宣言の最小打点がダマの最大打点より1000点以上高い場合に、供託1000点と以後の手変わり・守備の制約も説明する。未宣言の場面でリーチ可能だったとは仮定しない。追加のダマ計算は実打牌候補1件のみ。
- **待ち枚数と打点のトレードオフ**：見えていない待ちが2枚以上多い代わりに条件付き打点が1000点以上低い、という相反する選択肢も比較する。どちらかを誤りと断定しない。従来の枚数・打点とも優る比較も維持する。
- **1〜2向聴で他家のリーチを受けた場面**：実打牌と手持ち現物で、向聴数と受け入れを比較。3向聴以上の現物候補とは区別する。現物はそのリーチ相手への事実であり、全員への安全、放銃率、打点込みの押し引きEVまでは評価しない。
- ツモ打点の計算は他家リーチがあっても手牌上の条件付き試算として利用できるようにする。リスクや点差を含めた総合推奨とは扱わない。自家リーチ後の強制打牌は対象外のまま。
- 新カテゴリは `sanma-rules-v5`。署名受信で各カテゴリの数値と関係を検証し、監査で当時の公開状態・実宣言と照合。旧v1〜v4の互換性は維持。同じ打牌の宣言比較は、単なる推奨一致の称賛とは区別する。
- 復元件数、各席の候補上限、Python合計12件、7秒の子プロセス上限、workerの隔離と時間上限を維持。D1照会・台帳書込み・投稿を増やす仕組みは追加しない。ロン、フリテン、裏ドラ・一発、和了率、放銃率、染め手推定、最終着順EVは今回計算しない。
- 実Pythonによる待ち枯れの打点比較、単一候補の宣言比較、同じ打牌でもv5の講評が署名受信・キューに到達すること、再試行のKP・投稿非重複を検証する。本番配置のmergeメッセージに `[mahjong-review-audit]` がある場合は既存の監査workflowを読み取り専用で起動し、最新保存牌譜の解析を再確認する。支給・再投稿・変数変更は行わない。


## 2026-11-13：講評候補の分散と省略理由の診断（今回のPR）

直近の通常取得ログは `1 fetched / stored 1 / equal_review 0 reports` で、取得・保存は成功したが講評なしだった。画像の対局との同一性と、当時の個別の省略原因はまだ確定していない。以前のログは候補なし・無効化・解析異常を区別できなかったため、次の取得から診断できるよう変更する。

- 三麻の形比較は、各席の最初の対象6打で枠を使い切らず、復元済み候補を局ごと・離れた打目に決定的に分散して最大6件を選ぶ。守備も各席最大6件の候補に分散。結果や名前を使った選別やランダムな推奨はしない。
- 復元256件・最終局優先、Pythonの各席4/合計12件、既存の時間上限は維持する。これは全打牌の網羅解析ではなく、256件の復元に入らない局面や標準ルール外・自家リーチ後などは引き続き対象外。Python打点候補の選別方針は今回変更しない。
- 隔離workerの結果に内部診断を添え、呼出し側で固定カテゴリと件数だけに制限する。候補なし、復元対象なし、無効化、予算上限、タイムアウト、worker異常、計算器状態などを区別する。診断callbackの失敗は支給・解析結果に影響しない。
- 通常fetcherは認証済みsummary送信で `reviewDiagnostics:true` を指定。既存の口座・メンバー照合結果を再利用し、レポート欠落、不正形式、登録者向け候補なし、有効比較なし、投稿無効、キュー登録済みを返す。診断なしのAPI応答は従来どおり。診断用D1照会・台帳書込み・Discord投稿は追加しない。
- ログに牌譜ID・利用者ID・名前・牌・例外本文は出さず、固定状態と小さい非負整数のみ。過去の投稿の編集・再支給は実行しない。実対局で「改善場面がない」と「解析失敗」を確認するのは配置後の新規取得から。


## 2026-11-13：河とオーラスの点差を使う講評（今回のPR）

- 新しい三麻レポートは `sanma-rules-v4`。旧v1〜v3は引き続き受理。旧Workerはv4講評を採用しないため、配置の前後では講評が一時省略され得る。既存の結果・KP処理は継続する。
- リーチに対する現物候補に、その時点の相手の河・手持ち現物・相手が親かどうかを添える。数牌の筋は両面待ちとの関係だけで、中央牌は両側の筋が必要。字牌は筋判定しない。放銃確率や染め手の推測は追加しない。
- オーラス（東3／南3）の子で本場・供託なし、他家リーチなし、現在テンパイの局面を対象に、各待ちの実ツモ支払額で直後の点数順位を比較する。待ち枚数を減らさず、実打牌側の最良順位より別候補側の最悪順位が良い場合だけ講評する。同点、親の連荘、延長、リーチ宣言、本場・供託つきは対象外。
- 合計打点だけを点差に加算せず、親と子それぞれの支払いを差し引く。ロン条件・和了率・最終着順・ゲーム終了、本人の狙いは断定しない。これは押し引きや着順期待値の総合ソルバーではない。
- 既存の256打牌枠で最終局の記録を優先保持するオプションを三麻workerと監査で使用。通常の復元呼出しと四麻は従来どおり。Python計算枠は各席4・合計12のまま、最終局を優先する。D1照会・通知・KP支給を増やす仕組みは追加しない。
- 回帰検証には親子の非対称支払い・同点除外・待ちごとの不確実性・筋の両側判定・実Python計算・実隔離worker・最終局の枠確保・既存署名受信と配送を含む。実対局での講評評価と本番反映は別途確認する。


## 2026-11-12：三麻講評の選別と比較説明

「両面・三面張にしただけで褒められても学べない」という利用者の指摘への修正。以下は今回のコード変更であり、過去の配置記録とは区別する。反映先とCI結果は今回のPRを参照。

- 三麻は推奨と実打牌の一致だけでは講評しない。形・現物・条件付き打点の単純な称賛候補を生成せず、旧署名付きレポートに含まれる同種の候補も表示しない。旧形式自体の検証互換性は保持する。
- 強制的な「改善点＋称賛」の組み合わせを廃止。打点差、向聴数の差、同向聴の受け入れ差、限定的な現物候補の順に比較を選ぶ。同じ局・打目・席を重複表示せず、別の席の有効な比較も優先する。比較がなければ講評を足さない。
- 打点は実打牌と別候補の両方の条件付き点数・見えていない待ち枚数を示す。形は双方の向聴数または受け入れ枚数と、別候補で新しく受け入れになる牌の例を示す。現物は遠い手で守備を選ぶ場合の比較候補に限定し、押し引きの正解や他家への安全までは断定しない。
- この順序は編集上の優先度であり、期待値・ミスの重大さ・棋力のスコアではない。受け入れは山に残っている実枚数ではない。三麻の役・将来変化・押し引き・着順の総合評価を追加したわけではなく、難しい好手を証明して称賛するための比較情報も今後の課題。
- 既存の解析件数・時間制限は維持。収集済み候補内の選別を変更しており、全打牌を網羅するものではない。D1照会やDiscord投稿を増やす処理は追加しない。残高更新、対局結果の煽り、四麻C3解析には変更なし。
- 回帰検証：最善の形を残しただけの場面、現物を選んだだけの場面、旧レポートの称賛を除外する。大きい比較の優先・席の配分・重複排除・比較根拠の表示を検証し、実Python計算器と隔離workerを通る三麻試験も実行する。

## 実装済み

1. 三麻/四麻の共通復元器: 本人の手牌/ツモ、河、副露、暗槓/加槓/大明槓、北抜きと補充ツモ、立直/ダブル立直/受理、公開点数/供託/本場/ドラ。物理枚数と順序を検証。不明/不整合な処理からは当該局を除外する。
2. 四麻: 共通復元器からMJAIを生成。他家の立直後、チー/ポン直後、非立直時の各種槓以降も元モデルへ渡せる。本人の配牌/ツモだけを残し、他家手牌/隠れたツモ/壁/裏ドラ/未来情報は渡さない。槓の赤牌はその時点の遷移から取得し、後の手牌で補完しない。
3. 初期の親のツモが確定できない局では、親本人を除外し他家の解析を維持する。自家リーチ後の強制打牌、待ち変化を証明できない自家リーチ後の槓、不明な特殊ルールは除外する。
4. 四麻の実打牌と推奨打牌を、復元手牌/観測器の合法maskに照合。新しいレポートはversion2で「N打目」と表示。旧Workerはv2を拒否し旧本文だけを出すため、配置順による巡目誤表示を防ぐ。既存v1レポートの互換性は維持。
5. 三麻: 四麻モデルを流用しない独立の向聴数（通常/七対子/国士）、既知牌を引いた受け入れ、ドラ/赤の保持数。序盤10打以内、全員門前/立直なし、北抜き選択肢なし、オーラス/延長/極端な点差でない局面で、明確な形の差だけを批評/称賛する。**学習AI/打点/守備/着順ソルバーではない。**
6. 三麻の計算枠を、評価対象外の局面だけで使い切らない。
7. 推論結果は各席を1件ずつ先に選び、余り枠で真の称賛/代替案を選ぶ。未登録者1人の複数打牌だけで4枠が埋まる問題を解消。登録者IDを推論器へ追加送信したりD1照合クエリを増やしたりしない。
8. 既存の署名付きsummary受信/同じ投稿キューへ関西弁コメントを1～2件追加。順位・KP・遺物・和了・メンバー煽り・引用・メンションを維持。新配送は本文+embedへ収め、超過時だけ原子的に分割キュー登録する（第5段階参照）。
9. 任意推論は1バッチ最大1個の遅延起動worker。45秒/回・合計90秒で停止し、モデル取得/初期化/推論の失敗でも既存の牌譜/KPを継続。既存キャッシュを共有し、候補がなければモデル取得なし。

## 実データで見つけて直した不具合

- **全局除外:** 実牌譜の `opens` は3/4席分の空要素を持つ。`opens.length>0` を特殊ルールの証拠と扱ってしまい、共有復元器が全局を除外していた。実際の公開牌/有効値を調べるよう修正。
- 空のリーチ受理既定値から受理/供託を作らない。実受理は1000点減・供託1本増と整合確認。
- 旧人工fixtureで同じ牌の5枚目以降を引けていた。残り牌の山から引くfixtureへ修正。
- ポン直後の北抜き/自家槓を許す遷移を禁止。
- モデルがmask上では合法でも手牌にない牌を返す経路、実打牌自体がmaskで違法なケースを除外。
