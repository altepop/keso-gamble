# KESO COACH PR2-B：本人の試合への関連付けと前後の観察

承認済み設計 #628 のPR2-Bです。#631の本人限定の記録に、保存済みの本人のコンペを1件関連付け、予定保存前後の数値を確認できるようにします。自動の実施認定・因果効果の認定は行いません。v6トップの振り返り統合と記録専用コピーはPR2-Cに残します。

## 利用者が確認する三つの情報

1. 本人の実施申告、時間、試した回数、自由記述です。本人の記録であり、ログから検証した実施事実ではありません。
2. 保存済み試合の指標です。主指標1件、補助指標は最大2件で、K/D・KPR・DPR・ACS・ADR・HS%から選びます。分子・分母・有効試合数・除外理由・取得時点を返します。
3. 保存した確認方法と次の一場面です。試合数が少なくても本人の確認方法を提示し、未取得を失敗や0とは扱いません。

画面下部の本人限定の記録を開き、各実施記録の「本人の試合と数値を確認します」から明示的に読み込みます。個人メモにも本人の試合を関連付けられます。既存の記録・メモ・関連付けは共有要約や診断コピーへ含めません。

## 選定と比較

予定保存のサーバー時刻を固定の起点にします。起点前は終了時刻の降順、起点以降は昇順で各10試合です。同時刻は内部match_idで順序を固定します。探索範囲は片側30日、未来の終了時刻は含めません。起点と同時刻は後側です。

人物の確認済みPUUIDで参加を照合します。神戸の2アカウントを統合し、1試合を1件として扱います。同一ロスターに本人の複数アカウントがある行や不正ロスターは除外数へ残し、その穴を都合のよい後の試合で埋めません。指標の欠損も別の試合で埋めません。保存済みアーカイブが全試合を含む保証はありません。

K/Dは合計K÷合計Dです。KPR/DPR、ACS、ADR、HS%は既存coachPerformanceの有効性判定と定義を再利用します。キル時系列の完全性を一律の条件にしません。分母0はnullで、命中部位のHS%をヘッドショットキル率と混同しません。

同一マップ・エージェントの部分集合も、同じ最大20試合から提示します。マップ、エージェント、ロール、ACT、パーティー人数、チーム構成、勝敗の文脈と同時期の別の練習予定件数を返します。攻守・相手の強さ・VC等は未統制です。勝率を個人練習の成功判定に使いません。

指標ごとの両側の有効件数が5件以上で、両側の値を計算できる場合だけ「暫定の傾向」です。それ以外は「観察中」です。これは表示上の運用基準であり、有意差・ランク認定の基準ではありません。10件ずつそろっても効果を証明したとは扱いません。

後から登録した記録はplanned_at=nullのままです。自動の前後比較は作らず、本人が関連付けた試合の数値と確認方法を提示します。「終了時刻が起点以降」と「試合開始が練習後」は区別します。

## APIと保存

0014で実施記録へ内部match_id、主指標、補助指標JSONを、メモへ内部match_idを追加します。予定保存時刻の検索に索引を追加します。既存の削除済み記録には内容を復活させず、新しい選択情報も空にします。専用ensureは既存列を確認して加算し、再実行に対応します。

- GET practice/matches?record=…&kind=record|note&cursor=…：所有者の記録を確認して、周囲30日以内の本人候補を1ページ最大20件返します。カーソルは終了時刻と内部IDを不透明化したものです。
- POST practice/match：UUID、kind、expectedVersion、不透明matchRefと終了時刻を受け取ります。記録では主・補助指標も指定します。nullで関連付けを外します。
- GET practice/review?record=…&previous=…：本人の記録1件だけを読み取り、前後の観察と本人申告を分けて返します。

matchRefはドメイン分離したSHA-256(guild,subject,match_id)です。参照自体を認可には使いません。保存時には終了時刻の索引で最大21行を確認し、本人の現行PUUIDとロスターを再検証します。20件を超える同時刻候補は曖昧として409にします。生のmatch_idとPUUIDをレスポンスやログへ追加しません。自己申告の日付訂正後も、既に関連付いた本人の試合は再検証して維持できます。

関連付けと指標設定も既存versionのCASを使います。同じ更新の応答を失っても同一要求で再送できます。削除済みへの再送で復活しません。記録・メモの削除は内部関連付けと選択情報も消去します。

評価ルール、記録version、選択指標、対象ロスターと取得時点、関連付け、同時期の予定件数から評価versionを作ります。再読込時に前回versionと異なれば、記録またはデータの更新による再計算を画面で明示します。評価自体をD1へ自動保存するテーブルや書込みは追加しません。前後20試合は一つのSQL文で取得し、同じ読取のデータで再計算します。

## 境界と運用

既存のセッション・Origin・resolveCoachIdentityでguild/subjectを確定します。未認証401、許可外Origin403、別人・別guild・不明参照404、競合409です。全レスポンスno-storeです。節約モードの429は記録の認可後に重い読取へ適用し、保存・修正・削除は維持します。

明示的な読み込みだけで、初回分析やme/statusへ観察を同梱しません。Henrik追加取得、位置テーブル読込、KP・精算・通知の変更はありません。通常の入力・タイマー・折りたたみでAPIは呼びません。未保存の関連付けも通常の保存／破棄／戻るに参加し、他フォームの保存で失いません。認証切替・401・共有表示で入力・観察・前回versionを消去します。古いフォームと後着応答は別人の状態へ反映しません。永続ブラウザ保存はありません。

コストは返却行数とD1のrows_readを分けて測定します。専用の本番read-onlyベンチマークで、確認済み1人物の最大20試合について、新しい時間範囲のSQLと既存レポートのロスター取得部分を比較します。実行計画、実測rows_read、D1 duration、解析CPUを集計だけで記録します。解析CPUはCLI上の値で、Worker CPUや全レポートの費用とは呼びません。人工記録を本番へ書きません。

最終日本語チェック、375px/PC幅のv6比較、320px表示、Chromium/WebKit、所有者と共有の境界、CAS・再送・削除、欠損・連続窓・後登録・再評価を検証し、結果をPR本文へ残します。実ユーザー2人の認証済み本番操作を行えない場合は未実施と明記します。

本番負荷測定の対象解決は、非公開デプロイ用コピーの空のaccounts一覧に依存しません。既存の人物プロフィールと不変のKP紐付けから1人を解決し、resolveCoachIdentityでも検証します。これは管理用の読取専用測定だけであり、HTTP APIが使う暗号化済みの本番マッピングや認可を変更しません。
