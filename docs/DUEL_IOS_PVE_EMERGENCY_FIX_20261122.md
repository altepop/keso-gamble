# 緊急修正：Discord iPhone 決闘画面の３症状（2026-11-22）

## 実機報告（修正前）
1. 決闘に入ると「競馬／Mリーグ／カジノ／決闘／株」のサブタブが消える。
2. 「サーバーCPU攻略（PvE）を開く」を押すと別HTMLの再認証で「CPU戦を開けませんでした」。
3. エラー画面から「KESO PLAYに戻る」を押すと再びDiscord SDKの初期化が走り「画面を開けませんでした（Discordの起動確認）」。

## 原因と #758・#759 との関係
- `js/app.js` が `duelScreen` に下部ナビゲーションを渡す一方で、他の「遊ぶ」画面で使う `tabs:subTabs()` を渡していなかった。さらに `duel-view.js` はサブタブをレンダリングしていなかった。**画面コードの欠落**であり、KP接続とは関係ない。
- `duel-quality/duel-quality.js` の `scanPveEntry` が従来の `./duel-pve.html` と `./duel-pve.html#duel-rewards` の２リンクを注入していた。この専用ページの `duel-pve/boot.js` は `prepareDiscordActivity()` を新たに実行する。Discord iOSのActivity内で２度目のSDK初期化が失敗するとエラーを表示する。画面を戻す `index.html` へのリンクもアプリ全体を再起動するため同じ失敗が連鎖した。
- **#758** は認証済み決闘画面内の日替わりPvEを追加したが、従来の専用ページリンクは残った。**#759** はその画面への操作・運営UI統合を進めたが、旧リンクとの導線統一とサブタブ確認が不足していた。変更の時間的関係を示すものであり、SDK自体の不具合を断定するものではない。
- `duel-quality.js` は `js/` の内容由来キャッシュ対象外にもかかわらず、HTMLに固定のクエリバージョンが付いていた。旧遷移コードがiPhoneに残る可能性があった。スクリーンショット内の `web-ea2b658422679295` は最新デプロイの識別子ではないため、**端末キャッシュ混在の可能性**もある。ただし具体的な端末キャッシュ状態は計測しておらず断定しない。

## 修正
- `js/app.js` → `duelScreen({tabs:subTabs()})`、`js/duel-view.js` → 上部に５カテゴリタブを表示。
- 注入リンクをページ遷移しない `button` に変更。既存の認証済み画面内の `duel-pve-section` を開き、同じURL/Discord SDK/ウォレットを維持する。
- 既存の日替わりPvEに加え、６種目×３難易度を選んでサーバー権威PvEを開始する操作を統合。勝敗・報酬・秘密情報は従来どおりWorkerで確定し、操作IDで重複送信防止。
- 戦績・報酬ボタンも同じ画面内から認証付き `duels/rewards` を読み、取得結果のみ表示する。
- 旧リンクで直接専用ページに遷移した場合のエラー画面には履歴を優先する戻る操作を追加。
- `scripts/build-activity.mjs` で `duel-quality.js` の内容由来ハッシュをHTMLのクエリへ書き込む。端末に古い固定バージョンのファイルを再利用させない。

## テストと本番ゲート
- `scripts/duel-live-touch-browser-check.cjs`：390pxモバイルの本番画面コードを読み込み、５カテゴリ表示→PvE展開→サーバー対戦作成→報酬取得→「株」→「決闘」へ戻る一連の操作が**同じページURLのまま**成功することを確認する。Chromium/WebKitの両方でCI実行。
- `tests/duel-ios-pve-navigation.test.js`：画面のサブタブ、全種目PvE入力、報酬表示、別ページ遷移の再混入を単体検証。
- `scripts/post-deploy-smoke.mjs`：GitHub Pagesの**実際に配信されたHTMLとJavaScript**を読み、PvE移動先・サブタブ・専用スクリプトの内容ハッシュを検証。WorkerのKPステータスだけでは判定しない。
- CI全緑→head SHA固定マージ→同一main SHAのPages/Worker配備成功と本番スモーク→PR本文へ最終結論。自動検証が成功しても、**Discord iPhone実機での３経路の再確認は未確認のまま**とし、人手確認と区別する。

## 実機の再確認手順
1. DiscordのActivityを完全に終了し、KESO PLAYを新しく開く（旧画面の再読込ではなく再起動）。
2. 「遊ぶ」→「決闘」で「競馬／Mリーグ／カジノ／決闘／株」のタブが表示されることを確認。
3. 「サーバーCPU攻略（PvE）を開く」を押し、URL遷移やDiscord再起動エラーなしで同じ決闘画面のCPUパネルが開くことを確認。種目・難易度選択、戦績・報酬を開く動作を確認（任意の対戦開始はKPの既存報酬ルールが適用される）。
4. 「株」のサブタブへ移動し「決闘」に戻る。引き続きKP残高と既存対戦画面が表示されることを確認。

## キャッシュ自動再生成後の検証条件
- 独立した決闘画面拡張スクリプトのハッシュは `duel-<sha256先頭16桁>`。既存の `web-<sha256先頭16桁>` と別に、`index.html` の実配信タグで必ず確認する。
- GitHub Actionsが生成番号を更新した後の**最新head SHA**で全CIを再実行し、未完了・失敗中のチェックを無視してマージしない。
