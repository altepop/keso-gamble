# 一枚で億り人杯

通常レースとは別の、まれな特別開催。Discordユーザーごとに1枚だけ購入でき、倍率はゴールまで非公開。的中時の最大払戻しは馬券1枚につき100,000,000 KP。これは払戻総額で、純利益や必ず当たることを保証する数字ではない。既存の小額の遺物加算は別途適用される。

## 開催と馬券

- 2026-11-11 00:00 JST以降のみ。以前のカード・購入済み馬券を変更しない。
- **初回は2026年11月14日（土）22:00 JST固定**。馬券は21:45から21:59まで。初回週のランダム枠は置き換え、翌日などに重ねて祭りを開催しない。
- 2週目以降は各週50%の確率で1回。曜日と19〜23時の45分発走を決定的に選ぶ。平均では月約2回で、毎週開催を保証しない。
- 馬券代はユーザー確認済みの **1,000 KP固定**。 通常レースは従来の金額を選べる。
- 単勝・複勝・3連単から1つ。追加購入、買い直し、変更は不可。既存の週400,000 KP制限内で購入する。
- 稼ぎチャンネルへ3日前・前日・当日の朝9時（JST）に予告。さらに発走30〜15分前に `@everyone` で一度だけ盛り上げ告知を行う。発売開始の出馬表も従来どおり投稿する。通常の告知・出馬表・結果はメンション通知を無効にする。初回の予告は11月11日・13日・14日の朝9時。各予告は9〜10時のcronで一度だけキューへ登録する。停止などでこの時間帯を逃した予告は後でまとめて投稿しない。重複実行・再起動でも固定IDで登録を重複させない。Discord送信中断時の配送状態は既存のキューと同じ。
- 通常の出馬表通知、ライブ実況、結果通知を利用する。祭り専用の枠・案内・演出・高額的中見出しを加える。音声の自動再生は追加しない。

## 配当抽選

レース結果の抽選とは別に、サーバーでレースごとの秘密seedを生成し、先にSHA-256ハッシュを公開する。倍率は全参加者共通。通常のレース結果seedが発走時に公開されても、倍率seedは50秒のレース終了まで公開しない。

| 秘蔵倍率 | 確率 |
| --- | --- |
| ×10 | 40% |
| ×50 | 35% |
| ×200 | 20% |
| ×1,000 | 4.5% |
| ×10,000 | 0.5% |

馬券購入時の基礎オッズにこの倍率を掛け、最終オッズを100,000倍までに制限する。1,000 KPの馬券なら最大1億KP。外れは0 KP。単勝・複勝・3連単の当たりやすさは従来の抽選に従う。

倍率自体の平均は156.5倍だが、これは馬券の期待利益ではない。的中率、選択した馬券、上限の影響がある。低頻度・1人1枚に限定した、意図的に大きな通貨供給のある祭りとして扱う。

終了後は秘密seedと倍率を公開し、Activityでも事前ハッシュと倍率を照合する。通常の結果証明は従来通り。管理用の先読みも祭りでは拒否する。

## 決済と負荷

`kp_festival_seeds` と `kp_festival_tickets` を初回の対象レースで作成。口座操作INSERTのトリガーで `(guild, race, user)` を一意にする。二重購入は残高更新・台帳・状態保存と同じSQLite文で失敗し、全体がロールバックする。操作IDの再送は既存の結果を返す。失った状態JSONを使って購入制限を回避することもできない。

確定オッズはサーバーに数値で保存する。HTTPの状態・購入結果・再送結果だけを、終了前は `odds: null` にする。スラッシュコマンドの履歴、候補、出馬表、実況でも倍率を伏せる。支給は保存済みの確定値で従来通り一度だけ行う。

予告の朝9時台以外の通常レースで祭り専用SQLを発行しない。予告の候補日は純粋ロジックで判定し、該当する日の9時台だけ固定IDの存在確認を行う。全履歴走査、新しいcron、有料サービス、追加の秘密設定は不要。開催中の配当抽選はWorker内でキャッシュする。開催頻度や配当の後変更による過去レースの変更は避ける。

## 検証

純粋ロジック、実SQLiteの口座・台帳・同時購入・最大額支給、HTTPとスラッシュコマンドでの非公開、管理用先読み拒否をテスト。専用ブラウザ検証を `test:browser:all` に追加し、ChromiumとWebKitで購入・非公開・終了後公開・画面幅を確認する。テストは架空口座とAPIモックを使い、本番購入・通知は行わない。

## 直前の宣伝（2026-11-14追加）

発売15〜30分前のcronが最初に実行された時だけ、稼ぎチャンネルへ1レースにつき1通の `@everyone` 付き案内を登録する。固定ID `race-festival-hype:<race>` と既存キューの一意制約で、複数Workerや再起動による二重投稿を抑止する。時間帯を逃した過去の直前告知は再送しない。告知には発走時刻、15分間の発売時間、1,000 KP固定・1人1枚・オッズ非公開、最大1億KPが払戻総額の上限であること、購入導線を明記する。余計なD1全件走査、cron、Webhook、秘密設定は追加しない。
