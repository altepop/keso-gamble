# KESO DUEL ロードマップA P11新種目・P12シーズン運用 第三分割（2026-11-22）

## P11: 実際に遊べる追加種目
- 新種目「三目並べ」を既存の決闘画面に追加。ブラウザ内で人間 X とCPU O が交互に操作する。３連勝利、引き分け、合法手検証、手番検証、対局のリセットを実装。
- CPU難易度：かんたん＝合法手ランダム、ふつう＝即勝ち・即負け防止と中央優先、つよい＝全合法手を終局まで探索するminimax。強CPUは最善の人間の応手まで見て選ぶ。
- P9の６種目を妨げない。新種目は**ブラウザ内の無料練習**であり、サーバーPvE、PvP賭け、熟練度、KP報酬、遺物、ランキング対象には追加しない。追加にはD1チェック制約、報酬適格性、ボードサーバー権威・PvP・履歴の別途実装が必要。
- 画面に報酬対象外を明記。ブラウザによる「勝ち」はKPに反映されない。

## P12: 週次シーズン・イベント
- 月曜00:00 JST〜翌週月曜00:00 JSTを１シーズンとする。既存ギルドの**終了済みPvP対戦のみ**から勝敗・引き分けと順位を計算する。
- ランキングは既存のサーバー認証と所有者設定を通過した管理画面のみ。対象は直近500件上限、上限到達時は明示的に「一部集計」とし、通算ランキングとは呼ばない。キャンセル中・進行中・他ギルド・不正な勝者は集計しない。
- 既存の30日超の決闘履歴掃除に影響するため**恒久シーズンランキングではない**。日付境界と結果算定はサーバー側、順位は別のKP支払いに接続しない。
- 全メンバー向け週間ピックアップは既存6種目からテーマを順送りする。サーバー計算の公開イベントで、追加KPなし、本人の勝率補正なし、自動参加なし、参加費なし、賞品なし。ライブ大会イベントの実施・表彰・参加登録は未実装。

## P12: 無人の読み取り専用監査
- 既存の毎分Cronを**新設せず再利用**し、毎日日本時間03:17に限り、ギルド内の進行中対戦数と90日超の終了済み件数を２件の集計SELECTで数える。
- 監査結果は数値だけをWorkerのログに出力。削除、KP補正、再配備、Discord通知、追加課金、バックアップ、外部送信は行わない。
- 認証のある所有者UIの手動/表示中15分更新とは別の補助監査である。実際のCron到達とD1利用量は本番実行後に証拠確認が必要。
- 同一main SHAの本番配備で、Cronコードが配備されても、指定時刻の実行が成功するまで定期監査の**運用開始成功とは断言しない**。

## 次の残件・禁則
- 新種目のサーバーPvE/PvP統合、深い戦略モード、ライブ大会は別の設計・テストを要する。
- シーズン確定スナップショットの永続保存、報酬支払、全メンバー向け本人公開順位、成績の不正検証・履歴長期保全は未完成。勝手な報酬増減をしない。
- データ全量の復元可能な外部バックアップはR2等の安全な接続先・復旧手順が無いので保留。現行の直近確定50件の手動出力を完全バックアップとは呼ばない。
- P8端末実機、Discord２人遅延/VC実音到達、DO利用量等、人が必要な確認は未確認のまま。Renderの最新main配備とDiscord Botログインは別途成功済み。
- 全CI成功→head SHA固定マージ→同一main SHA Pages/Worker本番成功+スモーク→PR本文の結論追記を厳守。

## フェーズ12の日次監査・保持期間の修正
- 現行の対人決闘は30日経過した確定・キャンセル記録を掃除するため、**PvPの経過監査閾値を30日、PvEを90日**として別々に表示する。旧実装の両方90日表示は運営上不正確であった。
- 共通 `track` 関数は成功/失敗をD1のヘルステーブルに書くため、今回の監査だけは `track` を通さず `ctx.waitUntil` + ログの監査状態に切り替え、監査自身によるヘルスD1書込みをしない。Cronによる実使用量は運用後のCloudflareダッシュボード確認待ち。
- いずれも監査を読むだけで、削除・報酬支給・台帳変更は行わない。

## キャッシュ・CI確認
