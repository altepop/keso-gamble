# KESO COACH PR2-A：本人限定の実施記録・個人メモ

承認済み設計 #628 のPR2-Aです。Phase 2のうち保存・修正・削除を実装し、試合の関連付けと数値による効果確認はPR2-B、振り返りの統合画面と記録専用コピーは後続に残します。

## 利用者の操作

- v6の「この内容で実施します」は、選んだ最大3件の練習を予定としてサーバーへ保存します。実施済みの証明にはしません。タイマーは保存を行いません。
- 画面下部「実施記録と個人メモを確認します」で、本人の実施申告・時間・確認回数・実施日・振り返りを登録できます。
- 自分で決めた練習を予定として保存したり、過去分の本人申告として登録したりできます。後からの記録には予定時刻を作りません。
- 目標との関連付けは本人のactiveなprocess目標だけです。保存時の目標versionと内容を固定します。
- 個人メモは題名80文字・本文2,000 Unicode文字までです。複数行はそのまま保存し、HTMLとして実行しません。本人の実施記録へ任意に関連付けできます。
- 保存は明示操作だけです。未保存で移動すると「保存して移動／破棄して移動／入力に戻る」を選べます。認証切替・ログアウトでは古い入力を消去します。

## 保存・競合・再送・削除

専用0013でcoach_practice_recordsとcoach_personal_notesの2テーブル、3索引、2所有者固定トリガーを加算します。プロフィールへの複合参照と、人物ごとの未完了予定1件をDBで保証します。神戸の2アカウントは同じ人物の記録を使います。

新規はクライアントUUIDを固定し、更新はexpectedVersionのCASを使います。本文の所有者指定は認めません。同じ作成要求・直前と同じ更新要求の再送は、同じ結果を返して追加書込みを行いません。古い別内容の更新は409です。通信失敗では入力を保持し、同じ本文を再送するボタンを表示します。

削除は本文・目標スナップショット・練習スナップショット・実施結果・関連付けを消し、復活防止用のUUID・version・ハッシュ等の最小メタデータを残します。同じ新規要求を再送しても削除済み状態を返します。メモを関連付けた実施記録が削除されても、別に書いた本人メモ自体は勝手に削除しません。

予定のplanned_atはサーバー時刻で固定します。実施日・振り返りを訂正しても起点は変わりません。予定・カタログ・目標の元スナップショットは更新APIで変更できません。実施済み・未実施・不明は本人の申告であり、practiceVerifiedはfalseです。

登録済み練習は、クライアントとサーバーの両方がカタログとdiamond-v1表示方針のSHA-256を計算して照合します。サーバーは原本から文章を構成し、ミディアム→ハード、移動ボット、ストレイフONの条件も保存します。古いクライアントに最新のversionだけを渡して保存させず、カタログが異なる場合は画面全体の更新を案内します。個人が入力した練習は「本人の選択」と区別します。

## 本人境界とコスト

GET/POST /api/kp/coach/practice/records と /api/kp/coach/notes を追加します。guild・subjectは既存セッションとresolveCoachIdentityから確定します。他人のUUID・目標・関連付け、別guild、本文の所有者偽装を拒否します。未認証401・許可外Origin403、他人/不明404、CAS409、入力400/413、no-storeを継承します。

初回me/statusへは最大1索引読取の小さな未完了予定ポインターだけを追加します。履歴・メモ本文は同梱しません。記録の明示読込時だけ、実施記録・メモ・本人の現在目標を取得します。履歴は索引を使うカーソルで20件ずつです。初期一覧は予定1件と履歴20件までを返し、OFFSET走査・毎秒保存・自動ポーリングを行いません。

共有要約への移動時には、実施記録・メモ・未保存入力を消去します。認証世代をフォーム自体にも結び、古いフォームや再試行が別人のセッションで送信されないようにします。実施記録・メモは既存の診断コピー、共有summary/comparison/copyへ含めません。

Henrik追加取得・位置読込・KP付与・精算・通知・分析閾値は変更しません。効果確認と試合紐付けは未実装で、APIのpolicyでも利用不可と明示します。保存内容を分析結果や達成証拠として利用しません。
